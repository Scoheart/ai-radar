## SEP-3398 已获通过：MCP 规范改为每年 3 月、9 月两次发布，原定 12 月版顺延到 2027 年 3 月底
- 来源：网页/文档　记录者：MCP
- 链接：https://github.com/modelcontextprotocol/modelcontextprotocol/pull/3398
- 要点：Process 类 SEP，10/14 经 Core Maintainer 投票通过，10/26 PR 仍在更新文档（尚未合并）。规范每六个月发布一次，一般在 3 月和 9 月最后一个周二；每轮周期八个月、前后重叠两个月，设正副两位轮值 release manager 与统一 SEP 评审队列。过渡方案把 2026 年 12 月的发布目标挪到 2027 年 3 月底。
- 摘要：
  - 发布日不为未完成的提案让路：进版本的 SEP 必须在发布前 2.5 个月的软冻结前达到 Final 并合并，否则顺延到下一版。
  - Tier 1 SDK 要在发布前 1.5 个月出 beta，发布前 1 个月硬冻结，之后只允许全体 CM 投票通过的安全或互操作紧急修复。
  - 过渡方案让此前公布的 11/15 RC、12/15 正式版排期不再是目标，下一版改为 2027 年 3 月底。
- 启示：
  - 依赖新规范特性的路线图按 3 月、9 月两个窗口排期，并在 SDK beta 阶段就接入测试。
  - 想推动的 SEP 要提前找工作组或 CM 担保，赶在软冻结前做到 Final，包括一致性测试。
- 标签：mcp,spec,sep,release,governance
- 资源：spec=https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/seps/index.mdx

## SEP-3118 撤回核心提案：MCP Apps 内渲染表单 elicitation 改在 ext-apps 扩展里推进
- 来源：网页/文档　记录者：MCP
- 链接：https://github.com/modelcontextprotocol/modelcontextprotocol/pull/3118
- 要点：10/26 作者关闭核心规范 SEP-3118，理由是 App 渲染的表单 elicitation 只用到现有 elicitation 请求/结果结构、能力扩展点和 MRTR 流程，不需要改核心协议。方案整体并入 MCP Apps 扩展规范 ext-apps#733（仍在审），C# 与 TypeScript SDK 参考实现正按最新 main 刷新。
- 摘要：
  - 能力仍放在 io.modelcontextprotocol/ui 扩展内协商，宿主用 ui.resourceUri 把 elicitation 路由给 App 渲染，标准表单 elicitation 作为互通兜底。
  - 2026-07-28 版下，服务端把 elicitation/create 放进 MRTR 的 InputRequiredResult，宿主把 App 返回的 ElicitResult 填进 inputResponses 后带 requestState 重试。
- 启示：
  - 做 MCP Apps 的团队可以先按 ext-apps#733 设计表单交互，同时保留标准表单兜底，兼容不支持的宿主。
- 标签：mcp,mcp-apps,elicitation,sep,mrtr
- 资源：github=https://github.com/modelcontextprotocol/ext-apps/pull/733

## AGNTCon + MCPCon 北美回顾：SDK 累计下载 41.7 亿，议程重心转向安全与身份
- 来源：网页/文档　记录者：MCP
- 链接：https://www.infoq.com/news/2026/10/agntcon-mcpcon-2026/
- 要点：InfoQ 10/26 回顾 10/22–23 圣何塞大会。Den Delimarsky 称 SDK 累计下载 41.7 亿，116 个一致性场景约三分之一测安全，企业托管授权已在 Claude 上线，PoP 令牌和工作负载身份联邦处于草案。David Soria Parra 宣布 Claude Code 支持 MCP tasks；OpenAI 分享 ChatGPT 插件目录数据，要求每个工具都带 annotations。文中提示部分数字是台上说法，未附公开数据。
- 摘要：
  - 授权路线图：企业托管授权标为稳定，PoP 令牌与工作负载身份联邦为草案，终点是 agent 以自己的身份登录。
  - OpenAI：约四分之三的工具 schema 小于 1 kB，超大 schema 会先被裁掉参数描述；缺少工具 annotations 的服务器会被拒收。
  - 部分平台约 70% 流量已走 2026-07-28 的无状态模式；Claude Code 的 MCP tasks 让工具调用可持续数分钟到数天。
- 启示：
  - 自家 MCP 服务器给每个工具补 readOnly/destructive 等 annotations，并压小 schema，server instructions 控制在约 1000 字符内。
  - 认证方案提前为 agent 自有身份留位置，别长期依赖借来的用户 token。
- 标签：mcp,mcpcon,security,auth,tasks,community

## 官方 MCP C# SDK 2.0：HTTP 默认无状态、支持 MRTR 与可路由请求头
- 来源：网页/文档　记录者：MCP
- 链接：https://www.infoq.com/news/2026/10/mcp-csharp-sdk-stateless/
- 要点：InfoQ 10/26 报道微软发布的 C# SDK 2.0（实现 2026-07-28 规范）及随后的 2.1–2.3。去掉 initialize 握手和 Mcp-Session-Id，Stateless 默认 true；tools/call 带 Mcp-Method、Mcp-Name 头，网关可不读 body 路由；MRTR 用 InputRequiredException 取代调用中途反向请求。OAuth 更严格：RFC 9207 issuer 校验、要求 PKCE S256。
- 摘要：
  - 客户端先探测 server/discover，失败再回退旧握手；2.2 的 HttpServerSessionMode 让 2025-11-25 与 2026-07-28 客户端共用一个端点。
  - Tasks 移到可选包 ModelContextProtocol.Extensions.Tasks，与 1.3/1.4 的实验版不兼容；MCP Apps 有实验包。
  - 2.3 把 ServerInfo 改为可空，并提醒不要用服务端自报身份做安全判断；团队下一步重点是端到端认证授权。
- 启示：
  - .NET 服务升级前检查 Tasks 用法和长耗时 handler 的超时，必要时加进度输出。
  - 网关可以开始按 Mcp-Method/Mcp-Name 头做路由和限流，但以 body 为准并处理 HeaderMismatch。
- 标签：mcp,sdk,csharp,stateless,mrtr,oauth
- 资源：github=https://github.com/modelcontextprotocol/csharp-sdk
