## AWS 为 MCP 服务器上线企业托管授权：由企业 IdP 签发 ID-JAG，再换成 AWS 访问令牌
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://aws.amazon.com/blogs/security/secure-agentic-access-to-aws-with-enterprise-managed-authorization/
- 要点：11月25日，AWS Security 博客宣布 AWS Sign-In 支持企业托管授权（EMA）。这是 MCP 的扩展（io.modelcontextprotocol/enterprise-managed-authorization）：员工先用企业 IdP（如 Okta）登录 AI 应用，IdP 按组织策略签发短时 ID-JAG；应用把它交给 AWS Sign-In，换取与 IAM 角色绑定的 OAuth 访问令牌，无需员工再对每个 MCP 服务器单独授权。IAM 策略仍决定智能体可调用哪些 AWS 操作。这是把身份认证和资源授权分在两个信任域里处理，不是新的工具协议。官方同时提供配置文档，MCP 官网已有该扩展说明。
- 摘要：
  - 登录 AI 应用并不自动获得 AWS 权限；要由企业 IdP 签发 ID-JAG，再向 AWS Sign-In 换取绑定 IAM 角色的访问令牌。
  - 管理员在现有 IdP 里集中规定哪些应用可以访问哪些 MCP 服务器，员工不必对每个服务器再点一次授权。
- 启示：
  - 给企业部署 MCP 时，应把“谁登录了哪个 AI 应用”和“该应用能以谁的身份调用哪些云资源”分开配置，并沿用现有 IAM 最小权限，而不是给模型发长期密钥。
