## Amazon Cognito 为 MCP 客户端增加 CIMD 和动态客户端注册
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://aws.amazon.com/about-aws/whats-new/2026/11/cognito-client-id-metadata-documents/
- 要点：AWS 于 2026-11-19 宣布 Amazon Cognito 支持 OAuth 客户端标识元数据文档（CIMD）和动态客户端注册（DCR，RFC 7591），面向为 MCP 服务器做授权的场景。有了 CIMD，MCP 客户端可用 HTTPS URL 作为 client ID 并在该地址发布 JSON 元数据，Cognito 在登录时拉取并校验；运营方用 URL 模式策略把它映射到已有应用客户端，且只授予应用客户端和元数据文档共同允许的 scope 与授权类型，从而不必为每个外部助手单独创建和清理应用客户端。DCR 则在授权服务器元数据中公布注册端点，MCP 客户端可在运行时注册并获得 client ID；可要求带注册 scope 的访问令牌，也可开放注册。动态注册的客户端带有可筛选的 ID 前缀和类型。两项能力均在 Essentials 和 Plus 套餐、Cognito 全部可用区域提供。
- 摘要：
  - CIMD 让 MCP 客户端用自己的 HTTPS 身份登录，服务方不必为每个助手预创建应用客户端。
  - Cognito 同时提供 DCR，便于仍按运行时注册方式实现的 MCP 客户端接入，并可限制谁能注册。
- 启示：
  - 用 Cognito 保护远程 MCP 服务器时，优先评估 CIMD 策略映射；若必须兼容动态注册，应关闭完全开放注册或加上注册 scope。
- 标签：MCP,Cognito,CIMD,DCR,auth

## SEP-3567 提案：已获赞助但长期停更的 draft SEP 将进入休眠
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://github.com/modelcontextprotocol/modelcontextprotocol/pull/3567
- 要点：MCP 维护者 dend 于 2026-11-18 提交、11-19 仍有更新的治理提案 SEP-3567，目前为 draft，赞助人为 localden。提案规定：处于 draft 的 SEP 若连续 180 天没有作者或赞助人的提交、评论或评审，将标记为 dormant 并关闭其 PR，90 天时提醒一次。没有赞助人的既有规则不变，in-review 和 accepted 的 SEP 不受影响。动机是：目前只有 180 天找不到赞助人才会休眠；在 #3535 去掉 proposal 状态后，自动化已不再把任何 SEP 标为 dormant，于是已获赞助但实际停更的草案会一直开着。这只是草案，尚未被核心维护者接受。
- 摘要：
  - 草案尚未接受，只是补上“已有赞助人但长期没有实质推进”这一类 SEP 的休眠规则。
  - in-review 和 accepted 的 SEP 明确不在此次休眠范围内。
- 启示：
  - 跟踪 MCP SEP 时，要把新的治理草案和已经 accepted 的协议变更分开，避免把开 PR 当成规范已生效。
