## AWS 推出 API Portal 与 WAF AI Security，发现并防护 MCP、A2A 和 LLM 端点
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://aws.amazon.com/blogs/security/introducing-api-and-ai-security-on-aws-from-discovery-to-protection/
- 要点：2026-11-23，AWS 宣布三项能力正式可用：Amazon API Gateway 的 API Portal 用于发现 API 与 AI 端点；AWS WAF 的 API Security 托管规则组防护 API；AWS WAF 的 AI Security 托管规则组防护 AI 端点。发现可从流量日志和服务配置记录中识别 LLM、MCP 和 A2A 端点，无需额外部署探针或转发日志；未登记、对外暴露的 MCP 服务器会作为影子 API 出现。AI Security 做协议识别与合规检查，以拦截畸形的 MCP 和 A2A 消息；若启用内容检查，规则组会调用 Amazon Bedrock Guardrails，检测请求中的提示注入、越狱和有害内容，以及响应中的敏感信息。内容检查会产生额外的 Bedrock 费用。API Portal 覆盖 32 个区域，AI Security 在发布时可用于弗吉尼亚北部、俄亥俄、俄勒冈、伦敦、斯德哥尔摩、东京和悉尼等区域。
- 摘要：
  - API Portal 可从日志和配置中发现 LLM、MCP、A2A 端点，未登记的对外 MCP 服务器会以影子 API 出现。
  - WAF AI Security 可拦截畸形 MCP/A2A 消息，并可选用 Bedrock Guardrails 做提示注入和敏感信息检查，后者单独计费。
- 启示：
  - 在云上暴露 MCP 或 A2A 服务时，应先做端点发现，再把协议校验和内容护栏接到网关，而不是只靠应用自己声明。
- 标签：mcp,aws,waf,gateway,security
- 资源：docs=https://aws.amazon.com/about-aws/whats-new/2026/11/waf-ai-endpoint-discovery-protection/

## Canva MCP 正式开放，面向所有开发者与 Agent
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://www.canva.com/newsroom/news/canva-mcp-update/
- 要点：2026-11-23，Canva 宣布其 MCP 服务器正式开放，开发者可在 Developer Portal 注册并启用，不再排队。此前访问主要限于社区开发者，以及与 OpenAI、Anthropic 等合作方的连接器。官方称 MCP 已在 ChatGPT、Claude、Gemini、Muse 等助手中支撑大量设计任务；过去一个月约有 50 万人通过 MCP 注册 Canva，10 月用量接近翻倍（较 9 月增长 93%），首次使用的人中约四成是新用户。同步推出新的 REST API、扩展的 Canva CLI 和服务账号，设计结果仍可在 Canva 里编辑。这是生态开放，不是 MCP 协议本身的变更。
- 摘要：
  - Canva MCP 取消等待名单，向所有开发者和 Agent 开放，并同时提供 REST API、CLI 和服务账号。
  - 官方称过去一个月约 50 万人经 MCP 注册 Canva，10 月用量较 9 月增长 93%；首次使用者中约四成是新用户。
- 启示：
  - 评估 MCP 生态时，除协议和网关外，也应跟踪大型 SaaS 把只读连接器升级为可写、可嵌入工作流的开放节奏。
- 标签：mcp,canva,ecosystem,ga

## IETF 出现个人草案：用 SCIM 资源类型管理 MCP 服务器与工具组
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://datatracker.ietf.org/doc/draft-gaikwad-scim-mcp-server/
- 要点：2026-11-22 更新、标注日期为 2026-11-23 的个人 Internet-Draft（draft-gaikwad-scim-mcp-server-00，作者 Madhava Gaikwad）提出用 SCIM 资源类型在网关、私有注册表和 Agent 宿主之间传递 MCP 治理记录。草案定义 McpServer（端点、OAuth 受保护资源标识与授权服务器、所有者、可用主体、可选的已批准工具列表、以及是否获准使用）和 McpToolGroup（来自一台或多台服务器的命名工具集及其可用主体），并说明如何通过推送、拉取和 SCIM Security Event Tokens 同步变更。它明确不描述 MCP 服务器能力、不授权单次工具调用，也不是 IETF 或 MCP 官方 SEP 的背书；文档写明任何人都可以向 IETF 提交 Internet-Draft，本稿没有 IETF 背书，在标准流程中没有正式地位。
- 摘要：
  - 草案建议用 SCIM 的 McpServer 和 McpToolGroup 在网关、注册表和宿主之间同步 MCP 服务器的批准状态、所有者和可用主体。
  - 这是个人投稿的 Internet-Draft，不是 IETF 标准，也不是官方 MCP SEP。
- 启示：
  - 企业若要统一批准和撤回 MCP 服务器，可以关注这类身份治理接口，但在其进入标准或被主流网关实现之前，只能当作设计参考。
- 标签：mcp,scim,ietf,authorization,gateway
- 资源：spec=https://datatracker.ietf.org/doc/html/draft-gaikwad-scim-mcp-server-00
