## CodeRabbit 用 GPT-6.1 Sol 做跨仓库安全审查与沙箱利用验证
- 来源：网页/文档　记录者：代码审查
- 链接：https://openai.com/index/gpt-6-1-sol-coderabbit-code-security/
- 要点：OpenAI 案例：GPT-6.1 Sol 作为 CodeRabbit 安全 Agent 主力模型，把 PR 审查扩展到跨文件、跨组件及关联仓库（如共享鉴权库）的风险关联；对选定发现可在隔离沙箱尝试利用验证，并起草修复 PR 交人审批。官方称已在数千仓库标出安全问题，未公布误报率。
- 摘要：
  - 审查从单个 diff 扩展到关联仓库，并与传统扫描器、其他模型组合使用。
  - 发现、沙箱利用验证、修复 PR 连成闭环，但缺少公开的误报数据。
- 启示：
  - 安全类审查发现先在沙箱里验证可利用性再上报，可以压低误报噪音。
- 资源：x=https://x.com/OpenAIDevs/status/2114837274550747603

## Greptile 用 GPT-6 Astra 跑起应用来验证 PR
- 来源：网页/文档　记录者：代码审查
- 链接：https://openai.com/index/greptile-code-review-codex-astra
- 要点：OpenAI 案例：Greptile 针对 PR 启动开发服务器，用 computer use 模拟用户操作、切换移动端视口，靠视觉发现读代码看不出的问题；知识库经 MCP 提供给 Codex，用 AI 代码回滚率衡量上下文效果（未公布具体数字）。
- 摘要：
  - PR 验证从静态读代码扩展到真实运行和界面检查。
  - 以回滚率作为上下文是否有效的落地指标。
- 启示：
  - 把 AI 生成代码的 revert 率纳入审查效果指标，比单看评论数更能反映质量。

## Cursor Agent SDK 正式可用：Bugbot 同款审查 Agent 框架
- 来源：网页/文档　记录者：代码审查
- 链接：https://cursor.com/changelog/agent-sdk
- 要点：Agent 以代码项目定义（Markdown 提示词、TypeScript 工具），可响应 GitHub/GitLab/Bitbucket 的 PR、评论与 CI 事件；与 Bugbot、Security Review 共用 harness，模板含安全审查、owners 审批与 PR 自动修复。内置 eval 断言工具调用与输入，github replay 可把真实 PR 存成 eval 夹具。
- 摘要：
  - 审查 Agent 的提示词与工具变成可版本化、可回归测试的代码。
  - eval 断言的是调用了哪些工具，而非回复文本。
- 启示：
  - 上线自建审查 Agent 前，先用已人工审过的历史 PR 回放成夹具，检查能否抓到同样的问题。
- 资源：blog=https://cursor.com/blog/agent-sdk；docs=https://cursor.com/docs/agent-sdk/evals；x=https://x.com/cursor_ai/status/2114793714531102901

## Google 开源 Elephant-Goldfish Model：写代码前的设计审查门
- 来源：网页/文档　记录者：代码审查
- 链接：https://opensource.googleblog.com/2026/10/introducing-elephant-goldfish-model-plugin.html
- 要点：有完整上下文的 Elephant 会话起草设计文档，零上下文的 Goldfish 子 Agent 依次做理解复述、对抗式审查和实现就绪检查，通过后再写代码。Apache 2.0，支持 Antigravity、Claude Code、Codex；默认不含安全审查角色。
- 摘要：
  - 用无共享盲区的零上下文审查者，把审查前移到设计阶段。
- 启示：
  - 审查子 Agent 不要继承作者会话的上下文，先要求它复述设计，复述不对就说明文档有歧义。
- 资源：github=https://github.com/google/elephant-goldfish-model；docs=https://egm.dev/
