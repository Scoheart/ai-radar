## Semgrep Guardian：在编码 Agent 写代码时做安全检测并自动生成修复
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://semgrep.dev/blog/2026/semgrep-guardian-policies-ai-detection/
- 要点：2026-11-12，Semgrep 介绍 Guardian 的最新能力：把安全策略下发到开发者的编码 Agent 旁，在代码生成时检测并自动生成修复，目标是让整类问题不离开开发者电脑。Semgrep 自称已覆盖 1 万多名开发者：在编码 Agent 内提出的发现有 36% 被修复，作为 PR 评论提出的只有 10%；p75 修复时间在 Agent 内为 33 分钟，在 PR 上为 21 小时；95% 的扫描在 2 分钟内完成。新版本支持组织级自定义策略，并称可检测 IDOR、BOLA 等较复杂漏洞，以及拦截会引入恶意软件或可达漏洞的 lockfile 依赖变更。以上数据为厂商自报。
- 摘要：
  - 厂商数据表明，同样的安全发现在编码 Agent 内提出，比等到 PR 评论更容易、也更快被修复。
  - Guardian 同时做生成时检测、组织策略下发和供应链/lockfile 变更拦截。
- 启示：
  - 安全检查应尽量前移到 Agent 写代码的时刻，而不是只在 PR 扫描里做一次事后把关。
- 标签：code-review,appsec,coding-agent,semgrep

## ETH Zurich 论文：编码 Agent 会把仓库里已有的漏洞模式复制到新代码中
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.11455
- 要点：2026-11-08 提交的 ETH Zurich 论文《Coding Agents Propagate Vulnerabilities in Code Bases》研究已有漏洞会不会诱导编码 Agent 在新代码中写出类似问题。在 96 个需于已有应用旁实现新后端的任务中，不安全的邻居代码使“正确且安全”的实现平均下降 3.4%；在 20 对真实 C/C++ 项目的仓库级补全任务中，安全上下文与不安全上下文的平均差距达到 35.4%。当被要求解释实现选择时，Agent 在 76.5% 的情况下将其归因于跟随已有代码，同时在 69.9% 的情况下能够认出自己引入了漏洞。要求注意安全或跟随现有代码风格会减弱或增强这种传播，但都不能阻止。代码与数据见 https://github.com/eth-sri/vulnerability-propagation。
- 摘要：
  - 已有的不安全代码会成为 Agent 写新代码时的模板，C/C++ 仓库级任务上的差距明显大于普通后端生成。
  - 多数情况下 Agent 既跟着有漏洞的先例走，也能认出自己引入了漏洞。
- 启示：
  - 在把仓库交给编码 Agent 之前，应先清理已知不安全的示例代码；只加安全提示不足以阻止漏洞传播。
- 标签：security,coding-agent,vulnerability,research
- 资源：github=https://github.com/eth-sri/vulnerability-propagation
