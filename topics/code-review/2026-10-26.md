## Farol：开源 PR 合入风险地图，接在 AI 审查之后给审批人看
- 来源：网页/文档　记录者：代码审查
- 链接：https://github.com/winnin/farol
- 要点：Winnin 开源的 CLI 与 GitHub Action，不用大模型，而用 TypeScript 类型检查器、go/types、Python ast 构建声明图，追踪变更触达的页面、API、RPC 与后台任务，结合覆盖率、安全发现和契约破坏给出 0 至 100 风险分与三档审查结论；不执行代码、不阻塞合入。第三方实测显示对有类型的契约破坏识别准确，但无类型接口是盲区。
- 摘要：
  - Farol 是接在 AI 审查之后、给审批人看的风险地图。它不用大模型，而用 TypeScript 类型检查器、go/types 和 Python ast 建声明图，追踪变更触达的页面、API、RPC 和后台任务。
  - 风险分结合覆盖率、安全发现和契约破坏，给出 0 到 100 分，以及三档审查结论。分数描述影响面，不是另一条模型评论。
  - 它不执行代码，也不挡住合入。第三方实测里，有类型的契约破坏识别较准；无类型接口仍是盲区，不能当成已经覆盖。
- 启示：
  - AI 审查之后可以加一层不调用模型的风险图，给审批人看影响面，而不是再加一条评论。先接 TypeScript、Go 或 Python 里已经有类型检查器的仓库，用声明图追页面、API、RPC 和后台任务。
  - 这层不要挡住合入，也不要执行 PR 里的代码。0 到 100 分和三档结论只给审批人看。把它设成必过检查，就改变了原文里的用法。
  - 无类型接口要单独标成盲区，不要当成已经覆盖。接入前用一个无类型接口的 PR 看它会不会把盲区报成低风险。有类型契约上的准确，不能外推到没有类型的边界。
