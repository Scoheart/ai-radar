## Anthropic 推出 Claude Ship：审查、修复并按策略审批 PR
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://claude.com/resources/articles/introducing-claude-ship
- 要点：2026-11-23，Anthropic 宣布 Claude Ship 对 Claude Team 和 Enterprise 方案开放测试。它由已正式可用的 Code Review，以及测试中的 PR Steward 和 Claude Approvals 组成。Code Review 从多种角度审查 PR，对发现做对抗核验后分类并评论；官方称在 Claude Code 团队内部，Code Review 只是更广流程中的一层，6 月到 9 月合并的 PR 增加一倍以上，被回退的比例下降超过 40%，仓库可选择 Quick、Standard 或 Deep。PR Steward 负责让 PR 保持通过，处理失败的 CI、合并冲突和审查意见，但被设计为不批准、不合并；每次推送后会说明改了什么以及如何撤销，也可用 @claude 指令干预或停止。Claude Approvals 读取仓库里的策略文件，允许的常规变更可自行批准，也可要求更深入的人工签字，官方建议先以只观察模式运行，再纳入分支保护。开发者可在 Claude Code 中使用 /ship：推送、开 PR、审查并处理反馈与失败检查；能否合并仍取决于开发者权限和仓库分支规则。
- 摘要：
  - Claude Ship 把已正式可用的 Code Review，与测试中的 PR Steward、Claude Approvals 串成审查、修复和按策略审批的流程；面向 Team 和 Enterprise。
  - PR Steward 被设计为不批准、不合并；Approvals 读取仓库策略文件，官方建议先只观察，再纳入分支保护。
  - Claude Code 团队称，在 Code Review 作为更广流程一层的前提下，6 到 9 月合并 PR 增加一倍以上，回退比例下降超过 40%。这是单一团队的内部观察，不是独立对照实验。
- 启示：
  - 若让 Agent 参与审批，应把批准策略写成仓库文件，先观察再接入分支保护，并明确修复 Agent 不得自行合并。
- 标签：code-review,anthropic,claude-ship,pr-review
- 资源：docs=https://code.claude.com/docs/en/ship-command；blog=https://claude.com/product/claude-ship

## Azure DevOps 上 GitHub Advanced Security 的 Agentic Autofix 进入公开预览
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://devblogs.microsoft.com/devops/agentic-autofix-for-advanced-security-for-azure-devops-public-preview/
- 要点：2026-11-23，Microsoft 宣布 Agentic Autofix for GitHub Advanced Security for Azure DevOps 进入公开预览。管理员可在组织、项目或仓库启用。一次设置覆盖 CodeQL 与第三方 SARIF 工具的代码扫描告警，以及依赖漏洞告警；启用本身不会自动扫描或生成修复，由团队选择要对哪些告警生成修复。生成时，Copilot 编码 Agent 会结合仓库上下文、跨文件检查并打开 PR，带有 Copilot Autofix 标签和告警摘要，任务跑在 Azure Pipelines 中、使用专用的 GitHub Copilot（组织）身份。可用 .github/copilot-instructions.md 以及 .github 或 .agents 下的 SKILL.md 约束修复方式。官方写明它不会自行合并，也不是每条告警都能产出修复，仍需审查 diff、跑构建测试并通过常规 PR 流程合并。
- 摘要：
  - 公开预览里，安全告警可生成待审查的多文件修复 PR；启用不会自动开修，也不会自行合并。
  - 覆盖 CodeQL、第三方 SARIF 和依赖告警，并可用仓库内的 instructions 和 skills 约束修复方式。
- 启示：
  - 接入自动修复时，应默认要求人工审查和原有测试门禁，并用仓库内指令约束它使用项目已有的安全与依赖更新流程。
- 标签：code-review,autofix,azure-devops,github-advanced-security
