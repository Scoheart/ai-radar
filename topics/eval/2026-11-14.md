## Artificial Analysis 发布 Coding Agent Index v2.1：升级 FrontierCode-AA 2.0 与 Terminal-Bench 4.1
- 来源：据 X 上的报道　记录者：AI前沿者
- 链接：https://x.com/ArtificialAnlys/status/2121393821955334328
- 要点：Coding Agent Index 衡量模型在 agent harness 中的编码能力。v2.1 把 FrontierCode 升到 2.0（132 个真实任务，以仓库维护者是否会合并为评分标准），Terminal-Bench 升到 4.1（同 66 题，验证器更抗 reward hacking）。Claude Fable 5.2 与 Claude Opus 5.5 并列 58 分领先；整体分数平均下降约 5 分。
- 摘要：
  - 以“维护者是否会合并”作为评分口径，比单测通过更接近真实代码质量
  - 得分 48+ 的配置间单任务成本相差约 30 倍（$1.51 到 $44.22）
- 启示：
  - 内部 Coding Agent 评测应同时报告分数与单任务成本，并定期升级验证器以防 reward hacking
- 标签：coding-agent,leaderboard,terminal-bench

## Deepnote 开源 Agent Initiative Benchmark：测 Agent 何时该主动发言、何时该沉默
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://deepnote.com/research/benchmark
- 要点：在虚构公司 PageMantle（11 个服务、6 年记录、10GB 数据）的 Slack 中设 50 个工作情境，12 个前沿模型需自行调查并决定是否发言、发给谁、发在哪。双 LLM 评审 0–10 分，GPT-6 Astra 8.97 居首，GPT-6.1 Sol 8.65，Claude Fable 5.2 8.17。
- 摘要：
  - 把“该说还是该沉默”的判断与跨系统取证、投递位置合在一起评测，是主动式 Agent 的首个综合基准
  - 工具调用更多并不带来更高分，最重的两个模型 50 次中有 27/18 次超时
- 启示：
  - 主动式/常驻 Agent 要设调查预算并强制在发言与沉默之间做决定
  - 评测需固定 harness，再单独评 harness
- 标签：proactive-agent,benchmark,llm-as-judge
- 资源：github=https://github.com/deepnote/agent-initiative-benchmark

## Mercor 发布 OWE-Bench：26 个长周期工程/科研任务，连续打分
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://www.mercor.com/blog/introducing-owe-bench/
- 要点：OpenWorldEngineer 覆盖软件工程、物理工程、机器学习与科学计算，从 GPU kernel 到飞机设计，在未见用例上连续打分。Claude Fable 5.2 以 54.6% 领先（每次尝试约 2.11 亿 token），GPT-6 Astra 44.2%，Claude Opus 5.5 41.6%，无模型接近上限。
- 摘要：
  - 连续评分而非 pass/fail，能区分“做到一半”的长周期进展
- 启示：
  - 长周期任务评测可借鉴连续得分与 token 成本并报
- 标签：long-horizon,coding,benchmark

## Singularity-Bench：Agent 能否从零构建 AI 系统（预训练到集群编排）
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.16591
- 要点：CMU、NVIDIA 等提出 6 个端到端任务（预训练、中训练、后训练、推理、agent harness、集群编排），与成熟人类基线在相同硬件上比较；红队发现常规 Harbor 框架存在 reward hacking 漏洞，并提出 Breakwater 扩展。Opus 5.5 + Claude Code 的 Singularity-Index 为 1.25，其余 agent 平均 0.58。
- 摘要：
  - 评测框架自身可被 reward hack，需要专门加固（Breakwater）
- 启示：
  - 自建 Agent 评测沙箱应按 OWASP Agentic Top 10 做红队检查
- 标签：agent,benchmark,reward-hacking
