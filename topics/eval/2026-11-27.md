## TransHarness：从分布外轨迹演化出的干预策略，能迁移到新的编程基准
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.33757
- 要点：华中科技大学等提出 TransHarness。现有 harness 演化方法容易在演化所用的基准上过拟合。该方法从同一任务的成功与失败轨迹对比中学习干预策略，再用跨任务回放和独立语义筛选，保留能按当前任务证据做检查和纠正的策略。作者只用测试分布之外的 300 条源轨迹。论文报告 DeepSWE v1.1 为 76.4%、Terminal-Bench 2.1 为 95.5%，分别比最强基线模型 GPT-6 Astra 高 2.4 和 5.6 个百分点；在 DeepSWE 上回归率为 9.7%，低于 Self-Harness 的 13.0%。给 Qwen Code 加上后，DeepSWE 从 55.8% 升到 63.7%。分数来自论文，未见公开代码，未独立复现。
- 摘要：
  - 只用分布外 300 条轨迹，DeepSWE v1.1 和 Terminal-Bench 2.1 分别达到 76.4% 和 95.5%，比 GPT-6 Astra 高 2.4 和 5.6 个百分点。
  - 在 DeepSWE 上，相对基线 harness 的净提升来自 +13.0 的恢复和 −9.7 的回归，回归低于 Self-Harness 的 −13.0。
  - 论文复现显示，Meta-Harness 在独立演化集上提升，但在 DeepSWE v1.1 上下降，说明同一基准上的反馈不等于可迁移的改进。
- 启示：
  - 演化 coding agent 的 harness 时，不要只用同一基准的留出题做选择；应准备分布外的演化集，并在另一个基准上同时报告恢复和回归，而不只看净分。
- 标签：eval,transharness,harness-evolution,deepswe,terminal-bench

## 黑盒测试选择可以大幅降低智能体评测成本，但估分和找失败要用不同策略
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.34617
- 要点：代尔夫特理工大学评估了 14 种黑盒测试选择策略，覆盖 10 个智能体基准（含 SWE-bench Verified），每个基准 12 到 101 个智能体。作者报告：没有任何单一策略同时最擅长成功率估计和尽早暴露失败。在 20% 任务预算下，Category Partition 在 10 个基准中的 5 个上取得最低中位估分误差。对 GPT 5.2 Codex 的 SWE-bench Verified，该方法只跑 100 题而非 500 题，执行成本从 225 美元降到 47 美元，成功率估计的绝对误差为 0.8 个百分点。同样预算下，用 LLM-as-judge 做选择时，选中任务中有 53.0% 能暴露失败，随机抽样为 27.4%。分数来自论文，未独立复现。
- 摘要：
  - 没有一种策略同时最适合估分和找失败：Category Partition 更适合估计成功率，LLM-as-judge 更适合尽早发现失败。
  - 在 SWE-bench Verified 上，Category Partition 用 20% 的题目把 GPT 5.2 Codex 的执行成本从 225 美元降到 47 美元，估分绝对误差为 0.8 个百分点。
- 启示：
  - 回归测试智能体时，应先明确本次运行是要估分还是要找失败，再选抽样策略，不要默认随机抽一个子集。
- 标签：eval,test-selection,swe-bench,llm-as-judge,cost

## 让模型自己决定何时压缩上下文：紧预算下准确率可接近翻倍，但各模型用法差异很大
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.34147
- 要点：作者在 NVIDIA 开源智能体框架 NOOA 中比较两种策略：由 harness 在窗口满时触发压缩，以及由模型通过上下文 API 自己决定压缩什么、何时压缩。评测覆盖文档研究和机器学习工程，上下文预算从 8K 到 512K。作者报告，能有效使用该 API 的模型准确率更高，而且常常更省输入 token，在紧预算下更明显：GPT 6.1 在 32K 预算的 OfficeQA Pro v2 上从 21% 升到 56%；Kimi 最多可少用 41% 的输入 token。各模型调用 API 的频率、压缩激进程度和开始时机差别很大，提示也会改变时机。通过在编辑后复用未改动后缀的 KV cache，预填充计算最多降低 15%，准确率没有可测量的变化。这是受控对比，不是新的任务基准。分数来自论文，未独立复现。
- 摘要：
  - 在 32K 预算的 OfficeQA Pro v2 上，模型自主管理上下文使 GPT 6.1 的分数从 21% 升到 56%。
  - 模型何时开始压缩、压缩多狠，随模型和提示变化很大；有的模型会在仍有空余时过早压缩。
  - 推理引擎若支持在编辑后复用未改动后缀的 KV cache，预填充最多可减少 15%。
- 启示：
  - 给模型开上下文管理工具还不够，还要用不同预算和提示检查它会不会过早压缩，并把开始压缩的时机纳入评测。
- 标签：eval,context-management,nooa,compaction,long-context
