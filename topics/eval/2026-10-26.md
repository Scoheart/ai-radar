## SWE-DIVE：用户模拟器驱动的多轮编码 Agent 评测（Innsbruck × Microsoft）
- 来源：网页/文档　记录者：能力评测
- 链接：https://arxiv.org/abs/2610.30047
- 要点：把 SWE-bench、Terminal-Bench 等单轮任务改造成多轮交互：用户模拟器按不同行为模式逐步提需求，对话校验器检查模拟器是否忠于原始需求，最后跑测试判定完成。整体封装在 Harbor 环境中。
- 摘要：
  - SWE-DIVE 把 SWE-bench、Terminal-Bench 这类一次给完需求的单轮编码任务改成多轮交互。用户模拟器按不同行为模式把需求拆开、逐步提出，而不是开场就给全。任务有没有做完，仍以最后跑测试为准。
  - 对话校验器单独核对模拟器有没有偏离原始需求。测试只回答完成与否，不回答对话是否还忠于原题，所以这两步要分开记。校验失败不能和测试失败混成同一个分数。
  - 多轮交互、需求校验和测试判定都封装在 Harbor 环境里。评测可以沿用现有 Harbor，不必为了多轮再搭一套基础设施。
- 启示：
  - 评自己的编码 Agent 时，在单轮基准之外加一组需求会中途追加的多轮任务。只报 SWE-bench 或 Terminal-Bench 的单轮分，看不出 Agent 能不能跟着行为会变的用户把需求做完。先从已有题目改成多轮，不必新造题库。
  - 用户模拟器要单独做忠实度校验，确认它没有改写或丢掉原始需求。不校验的话，多轮分数里混进了模拟器的偏差，反映的不是 Agent。校验失败的轨迹和测试失败分开统计。
  - 多轮任务直接收进已经在用的 Harbor，对话、校验和测试走同一套封装。先确认现有 Harbor 任务能接上模拟器，再决定要不要扩环境。不要因为多轮就平行维护两套评测基础设施。
- 标签：coding-agent,multi-turn,user-simulation,swe-bench
- 资源：github=https://github.com/lorenzbrehme/swe-dive_usersim

## AgentVQA：跨五类 Agent 场景的离线视觉理解基准
- 来源：网页/文档　记录者：能力评测
- 链接：https://arxiv.org/abs/2610.31494
- 要点：从 23 个数据源人工挑选 1000 个真实 Agent 场景（Web、机器人、第一视角视频、游戏、空间规划）改造成离线 VQA，排名与对应在线评测一致。22 个 VLM 中最好仅 58.5%，主要错在视觉状态定位与追踪，而非任务理解或推理。
- 摘要：
  - AgentVQA 从 23 个数据源人工挑选 1000 个真实 Agent 场景，改成离线 VQA。场景覆盖 Web、机器人、第一视角视频、游戏和空间规划。它的排名与对应在线评测一致，可以先当作在线评测的离线筛选。
  - 22 个 VLM 里最好的只有 58.5%。这个数字是同一套 1000 题上的最好成绩，不是某一类场景单独的分数。
  - 错误主要出在视觉状态的定位和追踪，而不是任务理解或推理。拆错因时要先看模型有没有跟住画面里的状态。
- 启示：
  - 视觉模型上线前，先用这种离线 VQA 做筛选。原文里它的排名和对应在线评测一致，可以少跑几轮更贵的在线环境。筛选不能代替最终的在线确认，只能用来丢掉明显不行的模型。
  - 能力建设把「视觉状态定位和追踪」单列成一项，不要只看任务理解和推理。错因统计要把定位、追踪和理解、推理分开，否则会把看丢状态记成不会做任务。
  - 对照这 22 个 VLM 时，最好成绩是 58.5%。分数落在这附近，先查状态追踪，而不是先加长推理。题目来自 23 个数据源的人工挑选，换一批场景之前不要把 58.5% 当成所有视觉 Agent 的上限。
- 标签：vlm,agent,offline-eval

## Reward Model 评测盲区：成对比较测不到的跨 Prompt 分数可比性
- 来源：网页/文档　记录者：能力评测
- 链接：https://arxiv.org/abs/2610.31090
- 要点：成对评测会抵消同一 prompt 下的共享分量。作者提出以人类评分为参照的审计（跨 prompt 方差占比、兄弟回答回归、prompt 替换），在 HelpSteer2 上 6 个 RM 的跨 prompt 方差占比为 0.34–0.64，而人类接近 0。建议 RM 评测分别检查跨 prompt 变化、错误 prompt 敏感性与选择有用性。
- 摘要：
  - 成对比较会抵消同一条 prompt 下的共享分量，因此看不出分数能不能拿到别的 prompt 上比较。同一条 prompt 里谁更好，和跨 prompt 的分数是否可比，是两件不同的事。
  - 作者用人类评分做参照，检查跨 prompt 方差占比、兄弟回答回归和 prompt 替换。在 HelpSteer2 上，6 个奖励模型的跨 prompt 方差占比是 0.34–0.64，人类接近 0。
  - 评测要分开看三件事：跨 prompt 的变化、对错误 prompt 的敏感性、选择是否有用。只报成对偏好准确率，会漏掉这三项。
- 启示：
  - 选用奖励模型时，成对偏好之外加一层审计，看分数能不能跨 prompt 比较。审计对照人类评分，至少包括跨 prompt 方差占比、兄弟回答回归，以及把 prompt 换掉之后分数变不变。HelpSteer2 上那 6 个模型的方差占比是 0.34–0.64，人类接近 0，不能假设模型分数和人类一样可比。
  - 评测清单分成三列，分别记录跨 prompt 变化、对错误 prompt 的敏感性、选择是否有用。某一列失败就不要用一个总分把它盖住。错误 prompt 上分数仍然很高的模型，不能拿来做跨题排序。
  - 这三项都用人类评分当参照，不要只在奖励模型之间互比。互比只能看出谁更偏离谁，看不出谁更接近人类那种接近 0 的跨 prompt 方差。
- 标签：reward-model,meta-eval

## 生成式 Reward Model 缩放律：静态判分准确率不决定下游优化质量
- 来源：网页/文档　记录者：能力评测
- 链接：https://arxiv.org/abs/2610.30765
- 要点：在创意写作上用 Qwen3 0.6B–14B 训练 GenRM：GRPO 训练的 Thinking 判官静态准确率更高，但作为在线 DPO 奖励源时，8 组匹配设置中 7 组反而是 SFT 训练的 Answer-Only 判官带来更高策略 Elo，存在评测器与奖励器之间的落差。
- 摘要：
  - 这项工作在创意写作上，用 Qwen3 0.6B 到 14B 训练生成式奖励模型。GRPO 训练的 Thinking 判官，静态判分准确率更高。
  - 把判官当成在线 DPO 的奖励源时，8 组匹配设置里有 7 组反而是 SFT 训练的 Answer-Only 判官带来更高的策略 Elo。Thinking 判官更准，没有变成更好的奖励。
  - 静态判分准确率和下游优化质量是两件要分开看的事。选在线奖励时，不能只看判官自己的准确率，还要看它接上优化之后策略有没有变好。
- 启示：
  - 决定哪个模型来当在线奖励时，不要用静态判分准确率拍板。先在同一批匹配设置里把判官接上在线 DPO，看策略 Elo，再决定用 Thinking 还是 Answer-Only。
  - GRPO 的思考链判官静态更准时，仍然要用下游策略的结果再确认一次。这里 8 组里有 7 组是 SFT 的 Answer-Only 更好，准确率领先不能直接当成奖励源领先。
  - 这组对照限定在创意写作，模型范围是 Qwen3 0.6B 到 14B。换任务或换到这个范围外的模型之前，按同样方式重跑「静态准确率相对在线 DPO 策略 Elo」，不要把 7/8 这个落差直接搬过去。
- 标签：reward-model,llm-as-judge,scaling
- 资源：github=https://github.com/RaychevAngel/generative-reward-models

## 据 X：What Does a Harness Buy? 换编码 Harness 的影响与重跑噪声相当
- 来源：据 X 上的报道　记录者：能力评测
- 链接：https://x.com/thomas_rehmer/status/2114274063505920387
- 要点：在 SWE-bench Verified 上对比 Claude Code、OpenCode、mini-SWE-agent：45 题困难子集上重跑与换 Harness 都翻转约 13% 的题；447 题上 Claude Code 与 mini-SWE-agent 相差在 5 分内，OpenCode 落后最多 9 分，其中一半来自输出上限截断。同模型同任务每题成本最多差 3 倍，主要来自每步前置提示（16,581 / 7,025 / 829 tokens）。作者建议报告 Harness 对比时附上同配置重跑。
- 摘要：
  - 在 SWE-bench Verified 的 45 道困难子集上，同配置重跑和更换 Harness 都会让大约 13% 的题结果翻转。换 Harness 看到的涨跌，先和这个重跑噪声比，再解释成 Harness 的作用。对比的三套是 Claude Code、OpenCode 和 mini-SWE-agent。
  - 447 题上，Claude Code 和 mini-SWE-agent 相差不超过 5 分。OpenCode 最多落后 9 分，其中约一半来自输出上限被截断。截断和答错要分开，否则落后会被全部算成模型或 Harness 的能力差。
  - 同一模型、同一任务，每题成本最多差 3 倍。差别主要来自每步前置提示的 token 数，三套分别是 16,581、7,025 和 829。原文没有把这三个数逐一对应到哪一套 Harness。
  - 报告 Harness 对比时，应附上同配置的重跑结果。没有重跑，困难题上大约 13% 的翻转就无法和 Harness 差异分开。
- 启示：
  - Harness 对比必须附上同配置重跑。45 道困难题上，重跑本身就会翻转大约 13% 的结果，和换 Harness 的翻转幅度相当。先把重跑方差写进报告，再声称某一套 Harness 更好。
  - 同一模型、同一任务的成本差到一倍以上时，先查每步前置提示的 token：这里三套数字是 16,581、7,025 和 829，最多差 3 倍。先砍前置提示，再考虑换模型，引用时不要自行指认哪个数属于哪一套。
  - 输出被截断要单独记录，不要算进模型能力差距。OpenCode 最多落后的 9 分里约一半来自输出上限截断。报告里把截断题和真正答错的题拆开。
- 标签：harness,swe-bench,variance
- 资源：paper=https://arxiv.org/abs/2610.04433；github=https://github.com/YangzeLiu/what-does-a-harness-buy
