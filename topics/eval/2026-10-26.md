## SWE-DIVE：用户模拟器驱动的多轮编码 Agent 评测（Innsbruck × Microsoft）
- 来源：网页/文档　记录者：能力评测
- 链接：https://arxiv.org/abs/2610.30047
- 要点：把 SWE-bench、Terminal-Bench 等单轮任务改造成多轮交互：用户模拟器按不同行为模式逐步提需求，对话校验器检查模拟器是否忠于原始需求，最后跑测试判定完成。整体封装在 Harbor 环境中。
- 摘要：
  - 单轮编码任务被改成多轮：用户模拟器按不同行为模式逐步提出需求。
  - 对话校验器负责核对模拟器有没有偏离原始需求，完成与否仍由测试判定。
  - 整套评测封装在 Harbor 里。
- 启示：
  - 评自己的编码 Agent 时，补一组需求会中途追加的多轮任务，不要只报单轮基准。
  - 用户模拟器要单独校验是否忠于原需求，否则分数反映的是模拟器而不是 Agent。
  - 多轮任务可以收进现有 Harbor 环境，不必另起一套基础设施。
- 标签：coding-agent,multi-turn,user-simulation,swe-bench
- 资源：github=https://github.com/lorenzbrehme/swe-dive_usersim

## AgentVQA：跨五类 Agent 场景的离线视觉理解基准
- 来源：网页/文档　记录者：能力评测
- 链接：https://arxiv.org/abs/2610.31494
- 要点：从 23 个数据源人工挑选 1000 个真实 Agent 场景（Web、机器人、第一视角视频、游戏、空间规划）改造成离线 VQA，排名与对应在线评测一致。22 个 VLM 中最好仅 58.5%，主要错在视觉状态定位与追踪，而非任务理解或推理。
- 摘要：
  - 1000 道离线 VQA 覆盖 Web、机器人、第一视角视频、游戏和空间规划，排名与对应在线评测一致。
  - 22 个 VLM 里最好的只有 58.5%。
  - 主要错在视觉状态的定位和追踪，而不是任务理解或推理。
- 启示：
  - 视觉模型可以先用这种离线 VQA 筛选，它的排名和对应在线评测一致。
  - 能力建设把「视觉状态定位和追踪」单列出来，不要只看任务理解和推理。
- 标签：vlm,agent,offline-eval

## Reward Model 评测盲区：成对比较测不到的跨 Prompt 分数可比性
- 来源：网页/文档　记录者：能力评测
- 链接：https://arxiv.org/abs/2610.31090
- 要点：成对评测会抵消同一 prompt 下的共享分量。作者提出以人类评分为参照的审计（跨 prompt 方差占比、兄弟回答回归、prompt 替换），在 HelpSteer2 上 6 个 RM 的跨 prompt 方差占比为 0.34–0.64，而人类接近 0。建议 RM 评测分别检查跨 prompt 变化、错误 prompt 敏感性与选择有用性。
- 摘要：
  - 成对比较会抵消同一条 prompt 下的共享分量，看不出分数能不能跨 prompt 比较。
  - HelpSteer2 上 6 个奖励模型的跨 prompt 方差占比是 0.34–0.64，人类接近 0。
  - 评测时应分开看跨 prompt 变化、错误 prompt 敏感性和选择有用性。
- 启示：
  - 选用奖励模型时，除了成对偏好，还要审计分数能不能跨 prompt 比较。
  - 评测清单分成三列：跨 prompt 变化、对错误 prompt 的敏感性、选择是否有用。
- 标签：reward-model,meta-eval

## 生成式 Reward Model 缩放律：静态判分准确率不决定下游优化质量
- 来源：网页/文档　记录者：能力评测
- 链接：https://arxiv.org/abs/2610.30765
- 要点：在创意写作上用 Qwen3 0.6B–14B 训练 GenRM：GRPO 训练的 Thinking 判官静态准确率更高，但作为在线 DPO 奖励源时，8 组匹配设置中 7 组反而是 SFT 训练的 Answer-Only 判官带来更高策略 Elo，存在评测器与奖励器之间的落差。
- 摘要：
  - GRPO 训练的 Thinking 判官静态准确率更高。
  - 把它当作在线 DPO 的奖励源时，8 组匹配设置里有 7 组不如 SFT 训练的 Answer-Only 判官。
  - 静态判分准确率不能代表下游优化质量。
- 启示：
  - 不要用静态判分准确率决定哪个模型来当在线奖励。
  - 思考链判官更准时，仍要用下游策略的结果再确认一次。
- 标签：reward-model,llm-as-judge,scaling
- 资源：github=https://github.com/RaychevAngel/generative-reward-models

## 据 X：What Does a Harness Buy? 换编码 Harness 的影响与重跑噪声相当
- 来源：据 X 上的报道　记录者：能力评测
- 链接：https://x.com/thomas_rehmer/status/2114274063505920387
- 要点：在 SWE-bench Verified 上对比 Claude Code、OpenCode、mini-SWE-agent：45 题困难子集上重跑与换 Harness 都翻转约 13% 的题；447 题上 Claude Code 与 mini-SWE-agent 相差在 5 分内，OpenCode 落后最多 9 分，其中一半来自输出上限截断。同模型同任务每题成本最多差 3 倍，主要来自每步前置提示（16,581 / 7,025 / 829 tokens）。作者建议报告 Harness 对比时附上同配置重跑。
- 摘要：
  - 45 道困难题上，重跑和更换 Harness 都会让大约 13% 的题结果翻转。
  - 447 题里 Claude Code 和 mini-SWE-agent 相差不超过 5 分；OpenCode 最多落后 9 分，其中约一半来自输出上限被截断。
  - 同一模型、同一任务的每题成本最多差 3 倍，主要差在每步前置提示的 token 数。
  - 报告 Harness 对比时，应附上同配置的重跑结果。
- 启示：
  - Harness 对比必须附上同配置重跑，困难题上重跑本身就会翻转大约一成的结果。
  - 成本差一倍以上时，先查每步前置提示的 token 数。
  - 输出被截断要单独记录，避免把截断当成模型能力差距。
- 标签：harness,swe-bench,variance
- 资源：paper=https://arxiv.org/abs/2610.04433；github=https://github.com/YangzeLiu/what-does-a-harness-buy
