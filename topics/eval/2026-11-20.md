## Arena.ai 推出 Agent Arena Index，并改用可跨期比较的分数刻度
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arena.ai/blog/introducing-the-agent-arena-index
- 要点：Arena.ai 于 2026-11-18 发布博客，用 Agent Arena Index 作为新的头条排行榜，覆盖超过 290 万次真实用户会话，并同时推出 Agentic Work、Agentic Coding、Agentic Chat、Task Outcome、Steering 和 Tool Use 六个分项指数；Alignment Index 仍作为并列指标保留。方法上取消 Tool Hallucination 信号（作者认为前沿模型已很少调用不存在的工具），把 Confirmed Success 改名为 Task Completion 但测量方式不变；新分数是对原净改进分数做 1000 倍缩放再加锚点，不改变排名，用于避免模型绝对表现上升却因对照池变强而掉分。官方把 7 月模型均分初始化为约 1000，1 个指数点对应信号标准差的千分之一。
- 摘要：
  - 新刻度不改变原有排名，但让同一模型的分数可以跨期比较，不再随对照池平均水平被动升降。
  - Tool Hallucination 信号被退役；头条指数综合 Task Completion、Praise vs Complaint、Steerability 和 Bash Reliability。
- 启示：
  - 看 Agent 排行榜时，要分清相对对照池的净改进和锚定后的跨期分数，避免把对照池变化误当成模型退步。
- 标签：leaderboard,Agent-Arena,arena.ai
- 资源：x=https://x.com/arena/status/2123126646983332177；docs=https://arena.ai/resources/agent-arena-signals

## ExecJudges：用可执行程序代替逐篇 LLM Judge 做相关性标注
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.24849
- 要点：arXiv 2611.24849 提出 ExecJudges：由前沿模型按检索主题写成可读、可执行的判定程序，用词面匹配、常规 NLP 库和候选池统计代替对每篇文档调用一次 LLM Judge。在 7 个 TREC 集合上，ExecJudges 与 NIST 评估员的一致性在 TREC DL 2019-2021 上达到 Claude Sonnet 5.5 作为 LLM Judge 的水平。若每个主题再提供少量人工标签，ExecJudges-L 在全部 7 个集合上与 NIST 的一致性都高于同样标签训练的逐主题分类器，并超过或与同条件 LLM Judge 相差约 0.05 的 Krippendorff’s alpha。程序给出的标签对官方 TREC DL 系统排序的 Kendall’s tau 为 0.87–0.94；每个主题一次性写程序花费 0.17–0.49 美元，之后不再产生判定费用。
- 摘要：
  - 在 TREC DL 2019-2021 上，主题级可执行程序与 Claude Sonnet 5.5 逐篇判定的人工一致性相当。
  - 写程序是一次性成本（每主题 0.17–0.49 美元），之后判定可复现、可检查，且不再调用前沿模型。
- 启示：
  - 大规模检索评测若要降低 LLM-as-a-Judge 的费用并提高可复现性，可先尝试把判定规则编译成可检查的程序，而不是对每条结果都调用一次模型。
- 标签：LLM-as-a-Judge,TREC,relevance,ExecJudges

## 3D GameDev Arena：108 个从零开发 3D 浏览器游戏的超长程编码基准
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.24073
- 要点：arXiv 2611.24073 发布 3D GameDev Arena：108 个从零开始的游戏开发任务，覆盖 14 种类型。Agent 只得到文本规格和 UI/UX 参考图，由自动的规划—实现—测试—修复流水线生成可独立运行的浏览器游戏。一次运行平均约 1,000 次模型调用，最长一次达到 14,407 次调用、21.3 亿 token 和 608 个资产。评测包括对照规格的代码功能验收、针对 3D 呈现和可玩性的 Agent 质检，以及公开 Arena 上的盲测成对人类偏好（Bradley-Terry）。作者初步结论是超长程 3D 游戏开发远未被解决，而且代码层面正确并不决定玩家偏好。公开 Arena 见 https://baibizhe.github.io/gamearena/ 。
- 摘要：
  - 任务规模远超常见写代码基准：平均约 1,000 次调用，最长一次超过 1.4 万次调用和 21 亿 token。
  - 作者指出代码功能验收通过，并不等于玩家更喜欢这款游戏。
- 启示：
  - 评测要做完整产品而不只是修仓库时，应同时看功能验收和人类偏好，不要只用测试通过率下结论。
- 标签：benchmark,coding-agent,game-dev,long-horizon
- 资源：demo=https://baibizhe.github.io/gamearena/
