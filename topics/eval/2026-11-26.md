## OpenClaw Foundation 发布 ShellBench：日常任务上头部模型约六成通过
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://openclaw.ai/blog/shellbench
- 要点：11月24日，OpenClaw Foundation 与 Parsewave、Hugging Face、Red Hat、UC Berkeley 等合作发布 ShellBench：100道来自逾1000万次匿名真实交互的日常任务，工作区中位188个文件；90道按721条标准（含381条安全）全部通过才算完成，10道用代码测试。12个模型、5种 harness、共53100次评测。五套 harness 平均，GPT-6 Astra 62.5%、Claude Fable 5.2 61.9%、GPT-6.1 Sol 61.4%，官方称 Sol 的预估 token 成本约为 Astra 的六分之一；Astra 三次中至少一次通过 75.1%，三次全过仅 48.8%。全部 run 中 15.7% 未过安全项；在已满足全部正确性标准的 26151 次中，仍有 9.9% 未过安全项。Kaggle 独立复现（OpenClaw 2026.10.5、高推理、每题3次）榜首为 GPT-6.1 Sol 64.3%。公开20题、留出80题。分数来自官方，未独立复现。据 X 上的报道，OpenClaw 与 Kaggle 官方账号同步公布。
- 摘要：
  - 五套 harness 平均，前三名只差 1.1 个百分点，即使最强模型也有约四成任务无法满足全部要求。
  - 正确不等于可用：在已满足全部正确性标准的 run 里，仍有 9.9% 未过安全项；Astra 三次全过只有 48.8%。
  - Kaggle 独立榜用的是单一 harness（OpenClaw 2026.10.5），榜首是 GPT-6.1 Sol 的 64.3%，与论文里五套平均的 Astra 62.5% 不是同一口径。
- 启示：
  - 评测日常助手时，应把安全标准与正确性分开统计，并报告多次尝试的稳定性，而不是只看单次通过率。
  - 工作区里的过时记录、冲突信息和钓鱼邮件应进入评测集，否则分数很难反映真实委托场景。

## AgenticPPL：读完终端输出后写下的 command 困惑度，才能正向预测 Terminal-Bench
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://wenhaochai.com/blogs/agentic-ppl.html
- 要点：11月25日，Wenhao Chai 发表方法博文 AgenticPPL。在 Terminal-Bench 2.1 的 Terminus-2 轨迹上，对整段轨迹算普通困惑度会把模型排反（开发集 Spearman ρ 为 −0.292）。该方法只取读完终端输出后写下的 command，并对单 token 截断后再平均。预先固定的检验中，开发集 ρ 为 +0.890；留出轨迹×开发集模型为 +0.854；留出轨迹×15个留出模型（21–37B，只测一次）为 +0.788，而普通困惑度为 −0.495。这是一次前向、无需沙箱生成的代理指标，不是新的任务基准。据 X 上的报道，作者账号同步发布了这篇感恩节博文。
- 摘要：
  - 普通轨迹困惑度在 Terminal-Bench 2.1 上把模型排反，主要反向信号来自终端输出。
  - 在预先留出的 15 个 21–37B 模型上，AgenticPPL 的 Spearman ρ 为 +0.788，普通困惑度为 −0.495；留出模型只测了一次。
- 启示：
  - 用困惑度代理智能体能力时，要先确认信号来自哪些 token；把终端输出和模型自己写的命令混在一起平均，可能得到相反的排序。
