## UserSWE：多轮动态用户下的仓库级修 Bug 评测，排名随交互轮数变化
- 来源：网页/文档　记录者：能力评测
- 链接：https://arxiv.org/abs/2610.29822
- 要点：腾讯混元把仓库历史与单轮基准改造成多轮任务：信息池限制模拟用户能透露的内容，人格链由 20,859 个真实开发会话校准；每轮都跑测试，由两个不同模型家族的 Agent 以测试结果为主证据写并把关判决。11 个 Agent、42 个仓库 72 题上，Claude Fable 5.1 一轮解决最多，GPT-6-Astra 第八轮最多，Claude Opus 5 在多数中间预算领先。
- 摘要：
  - 单轮成绩不足以刻画交互式编码能力，排名随交互预算改变
  - 判决以执行结果为主、模型判断只补测试无法覆盖的部分，并用跨家族双 Agent 把关
- 启示：
  - 内部 Coding Agent 评测应按交互轮数报告曲线，而不是只报单轮通过率
- 标签：coding-agent,multi-turn,user-simulation,benchmark

## SWE-Shift：任务执行中途环境变化，17 个编码 Agent 全部掉分
- 来源：网页/文档　记录者：能力评测
- 链接：https://arxiv.org/abs/2610.32196
- 要点：从同一份历史与工作区分出 Clean 与 Shifted 两条续跑，后者在 9 个时点注入与任务相关的变化（代码、依赖、运行状态、需求等 12 类，共 120 个场景）；成功要求完成任务、保住仍有效的工作并通过状态与证据检查。GPT-6 Astra 从 67.35% 跌到 24.79%，配对成功率 20.34%；工具/会话变化与过时证据两类所有系统配对成功率为 0。
- 摘要：
  - 在不变任务上成功，不代表能在更新后保住工作、恢复状态或刷新证据
  - 工具/会话变化与过时证据是当前所有系统的盲区
- 启示：
  - 长任务 Agent 评测要加入中途变更扰动，单独统计『保住已完成工作』与『刷新过时信息』
- 标签：coding-agent,robustness,benchmark
- 资源：github=https://github.com/JeixHuang/SWE-Shift

## SWE-Bench Pro 提示词点名了 81% 隐藏测试要调用的新函数，99.4% 的含义需重读
- 来源：据 X 上的报道　记录者：能力评测
- 链接：https://x.com/con_golias/status/2114495930074325295
- 要点：作者比对 SWE-Bench Pro 原版 731 题与 V2 642 题的提示和隐藏测试：issue 文本只点名 10% 的新函数/类/字段，加上 Scale 补的 requirements 与 interface 字段后达 81%，V2 修复后升到 88%。作者认为这是为避免命名失配而有意设计，修复让基准更公平；但 99% 衡量的是『按人写的规格实现』，最难的规格部分由基准提供。复现脚本已开源。
- 摘要：
  - SWE-Bench Pro 的高分主要衡量按规格实现，而非从模糊需求出发决定做什么
  - 隐藏测试基准在『避免命名误判』和『泄露解法』之间存在固有取舍
- 启示：
  - 自建 Coding 评测时统计提示对测试所需接口的覆盖率，并分开报告给接口与不给接口两种设置
- 标签：swe-bench-pro,benchmark-audit,spec-leakage
- 资源：github=https://github.com/con-golias/workings；paper=https://arxiv.org/abs/2610.24206

## Legal AI Errata：对 Harvey、Anthropic 等 8 个仓库的法律 AI 基准与技能提交 16 条更正
- 来源：据 X 上的报道　记录者：能力评测
- 链接：https://x.com/SamRedlich/status/2114805737683570803
- 要点：作者向 Harvey、LegalQuants、Anthropic、General Legal、Thomson Reuters、Crosby Legal 发布的法律基准、技能与模板提交 16 条更正（15 条附补丁），建立公开登记库，记录引用版本、官方法源、替换文本及提交/回复/解决时间。基准部分的缺陷落在评分细则、标准答案、参考答案或渲染代码上；13 条评为 high（正确答案被判错或会导致错误结论）。

- 启示：
  - 为内部评测集建立勘误流程：固定版本、标注依据、记录修复状态

## Artificial Analysis 发布 Code2Video-AA：用代码做营销视频，Opus 5.5 领先 93 分
- 来源：据 X 上的报道　记录者：能力评测
- 链接：https://x.com/ArtificialAnlys/status/2114845067026571365
- 要点：独立实现 HeyGen 的 Code2Video Bench：114 个设计简报，模型无工具单次输出 HyperFrames HTML，断网渲染成视频，由 Gemini 4 Argon 判官在 5 个维度两两比较，3.5 万+ 判决给 27 个模型算 Elo。Claude Opus 5.5 以 1536 领先 93 分但每题 .08；GPT-6.1 Sol 第四（1369）每题 --.31；开源最好落后至少 483 分。
- 摘要：
  - 渲染失败直接输掉所有对比，把可执行性纳入审美评测
  - 单任务成本跨度超 300 倍，性价比与绝对分数需一起看
- 启示：
  - 生成类评测可用『渲染后成对比较 + 多维 Elo』替代绝对打分，并同时记录每题成本
- 标签：llm-as-a-judge,code-generation,video,leaderboard
- 资源：leaderboard=https://artificialanalysis.ai/evaluations/code2video-aa；blog=https://artificialanalysis.ai/articles/code2video-aa
