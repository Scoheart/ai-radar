## Google DeepMind 与 Artificial Analysis 发布 MKA：200 项多模态知识工作评测
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://blog.google/innovation-and-ai/models-and-research/gemini-models/multimodal-knowledge-agent-benchmark/
- 要点：2026-11-10，Google DeepMind 与 Artificial Analysis 发布 Multimodal Knowledge Agent（MKA）基准，由 10 个行业、83 个职业的专家共建 200 道需处理视觉复杂文件的知识工作题；每题约 70 条专家是非量表，事实准确性占 75%、视觉设计占 25%。全部模型在开源 harness Stirrup 中运行，由非 Google 模型驱动的 agentic autorater 打分，与专家一致性为 96%；200 题集保密，另有 10 道公开题。Artificial Analysis 头条指标 Climb WSR：Claude Fable 5.2 为 57%，Gemini 4 Carbon 为 54%，Claude Opus 5.5 为 53%。AA 称 Fable 平均约 31.97 美元/题，Carbon 约 6.29 美元/题；Google 则称 Carbon 平均成本约为最高分模型的六分之一。同任务上，受测模型平均轮次约在 30 到 130 之间。
- 摘要：
  - MKA 针对必须阅读图纸、原理图、扫描件等视觉文件才能完成的专业交付物，而不是可纯文本求解的知识题。
  - Artificial Analysis 用 Climb WSR 作为头条分：Claude Fable 5.2 57%，Gemini 4 Carbon 54%，Claude Opus 5.5 53%；成本差异超过质量分差。
  - 200 题评测集保密以防泄漏，另有 10 道公开题供检查格式；autorater 与专家一致性为 96%。
- 启示：
  - 做知识工作 Agent 评测时，应同时看质量、单题成本和平均轮次，避免只比较头条准确率。
  - 视觉依赖任务要把输入文件真正作为必选项，并用专家量表区分 Climb 与 Regression 指标。
- 标签：benchmark,multimodal,agent,llm-as-judge,leaderboard
- 资源：blog=https://artificialanalysis.ai/articles/google-deepmind-multimodal-knowledge-agent；leaderboard=https://artificialanalysis.ai/evaluations/mka

## ARE-bench：用真实研究会话和工作区评测研究 Agent 能否推进进行中的项目
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.14364
- 要点：2026-11-10 提交的 ARE-bench 用研究者本人项目中的真实会话和未清理工作区构建 75 个任务，覆盖 7 个研究阶段、33 项需求、150 个子需求，共 1,173 条二进制 checklist。每项任务锚定真实请求，保留仍有效的历史要求作为背景，并回放当时的完整工作区。七款前沿模型中，最强者也只在 66.2% 的任务上通过全部 checklist；若只检查交付约定和一般规范，三款模型约 69% 通过，一旦加上历史与工作区要求则降到 28.4%–40.0%。Design 与 Execution 对所有模型都偏难。项目页：https://arebench.com。
- 摘要：
  - 评测重点是在进行中的项目里尊重既有决定和凌乱工作区，而不是在干净仓库上做独立任务。
  - 忽略历史与工作区约束会高估研究 Agent，并掩盖模型之间的差距。
- 启示：
  - 评测研究或长周期 Agent 时，应保留历史约束和未清理工作区，而不是只检查最终交付格式。
- 标签：benchmark,research-agent,rubric
- 资源：demo=https://arebench.com

## 论文指出 Agent 基准往往先失去区分度，问题在计分而不只在题目变容易
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.13541
- 要点：2026-11-10 提交的论文重评包括 SWE-bench Verified、Terminal-Bench 在内的 8 个基准后认为，排行榜饱和很大程度上来自测量方式：多数 Agent 基准把一次运行压成 pass/fail。SWE-bench Verified 前十名分差小于其测试误差；ALE-Bench 用竞赛分能把前十分成三档，但按中位人类作对/错打分时，五款模型在 40 题中通过 39 题，尽管近一半运行超过该人类水平。作者提出带日期锚点的 clipped log-ratio 分数，并把成本作为单独坐标轴；在 Terminal-Bench 重跑中，pass/fail 并列的模型在被丢掉的连续量上可相差十倍以上。
- 摘要：
  - 作者认为饱和常常是计分太粗、且被参考答案封顶，而不是任务已经用尽。
  - 提高通过门槛只会把问题挪走；分级计分才能在同一批任务上重新拉开档次。
- 启示：
  - 维护排行榜时，除了换更难的题集，也应检查 pass/fail 是否已经无法区分头部模型，并单独报告成本。
- 标签：benchmark,methodology,leaderboard,scoring

## AgentScript-Eval：企业 DSL 上从零编写 Agent 定义几乎全部失败，技能写法比模型规模更关键
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.13183
- 要点：2026-11-09 提交的 AgentScript-Eval 用 Salesforce Agentforce 的声明式 DSL AgentScript 收集 100 个真实任务，覆盖按规格编写、调试损坏定义和优化已有定义。五款模型 zero-shot 时最好只到 25.0% pass@3，从零编写全部为 0%。模型规模和价格对成功率预测很弱：一个 31B 开源权重模型编译率最高（48.0%），并在部分正确率上追平最强前沿模型且 token 成本最低。加上 agentic 的编译-修改循环大约使部分正确率翻倍。同一 skill pack 作为普通文档得 28%，作为 live plugin 只有 14%，改写其中一项 skill 后升至 37%，为文中最佳。
- 摘要：
  - 在预训练语料里很少出现的企业 DSL 上，从零编写 Agent 定义对所有 zero-shot 模型都是 0%。
  - 技能的组织与措辞比是否做成插件、也比模型更大更贵，更能改变成绩。
- 启示：
  - 给编码 Agent 提供技能时，应先把关键指导改写成渐进披露的入口，并用编译-修改循环验证，而不是只换更大的模型。
- 标签：benchmark,skills,coding-agent,dsl
