## Google Agent Retrieval 公开预览托管导入与 SearchDocuments，一次调用返回带出处的段落
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://developers.googleblog.com/from-files-to-cited-answers-in-one-api-call-managed-ingestion-and-searchdocuments-in-agent-retrieval/
- 要点：11月24日，Google 为 Agent Retrieval（原 Vector Search 2.0）公布两项公开预览：托管导入可解析、切分并用 Gemini Embedding 2 嵌入 Cloud Storage 中的 PDF、DOCX、PPTX、XLSX 和 TXT；SearchDocuments 一次调用返回带页码或时间戳的匹配段落。文档与视频需分库。官方称 18 份 Alphabet 投资者 PDF 约 9 分钟可检索，19 分钟视频按画面和语音检索每次约 0.3–0.5 秒。也可按文档过滤、做重排序，并返回元数据。这是官方测试，未独立复现。
- 摘要：
  - 托管导入把解析、切分和嵌入收进一次导入，查询侧一次 API 调用就返回带页码或时间戳的出处。
  - 文档和视频要分开建库；官方演示是 18 份 PDF 约 9 分钟可查，视频查询约 0.3–0.5 秒。
- 启示：
  - 自建知识库时，应要求检索结果带页码或时间戳，并能按单个文件缩小范围，而不是只返回一段无出处文本。
- 标签：knowledge-base,rag,google,agent-retrieval,document-parsing

## .NET 预览 DocumentExtractionClient：用统一结构抽取 PDF、扫描件和 Office 文件
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://devblogs.microsoft.com/dotnet/document-extraction-dotnet-preview/
- 要点：11月24日，Microsoft 发布 Microsoft.Extensions.DocumentExtraction 预览，其中的 DocumentExtractionClient 把 PDF、扫描件和 Office 文件抽成统一的标题、段落、表格和插图结构。提供者可换成进程内 PDF 解析、任意 IChatClient 背后的视觉模型，或 Azure Content Understanding，再接入 Microsoft.Extensions.DataIngestion 做检索增强生成。这是预览 SDK，不是新的评测基准。
- 摘要：
  - 不同解析器共用同一套抽取结果结构，换提供者不必重写下游切分和入库代码。
  - 目前仍是预览，官方也写明与 DataIngestion 的组合还会继续简化。
- 启示：
  - 文档解析层应先产出带层级和表格结构的中间表示，再送去切分和嵌入，避免把页眉页码一并切进知识库。
- 标签：knowledge-base,document-parsing,dotnet,rag,microsoft

## Amazon 论文：把生成的 SPARQL 解析成单跳图遍历计划，而不是直接执行查询
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.31771
- 要点：11月24日，Amazon 团队提交论文（arXiv 2611.31771）：先用稠密检索定位相关区域，再让模型把图遍历计划写成 SPARQL，但只解析该查询、并不直接在图上执行，然后沿 Wikidata 的推理路径确认和补全段落。在统一语料和阅读器、同一配置下，作者报告 HotpotQA 为 62.5/75.1 EM/F1，2WikiMultiHopQA 为 73.5/81.0，MuSiQue 为 37.1/50.0，均高于其复现的 HippoRAG2、T²RAG 和 IRCoT。直接执行生成的 SPARQL 最多掉 11.4 EM，主要因为查询返回空结果，而不是语法错误。分数来自论文，未独立复现。
- 摘要：
  - 关键设计是把 SPARQL 当作可解析的遍历计划，而不是拿到查询就执行；直接执行最多掉 11.4 EM，空结果是主因。
  - 在三个多跳问答基准上，同一套配置都高于作者复现的 HippoRAG2、T²RAG 和 IRCoT。
- 启示：
  - 用大模型规划知识图谱遍历时，应先检查生成查询是否会得到空结果，并保留解析后的路径，而不是把查询直接交给图引擎。
- 标签：knowledge-base,graphrag,sparql,wikidata,multihop-qa
