## LlamaIndex 发布 ParseBench-2：按错误严重度校准的文档解析基准
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://www.llamaindex.ai/blog/introducing-parsebench-v2
- 要点：2026-11-12，LlamaIndex 发布 ParseBench-2。案例从 ParseBench-1 的 2.1k 增至 4.3k，新增表单作为第六个评测维度，并检查 1,025 张图表的全部数值。团队定义了 330 类错误，按 critical、major、minor、harmless 标定分数应下降多少，再用这些测试去校准文本、表格、格式、图表、版式和表单六类确定性指标，以避免无关格式问题扣分过多、关键数字错误扣分过少。数据集、评测代码和论文已公开。据 X 上的报道，LlamaIndex 创始人 Jerry Liu（@jerryjliu0）于同日宣布该基准。
- 摘要：
  - ParseBench-2 用人工标定的错误严重度去校准确定性指标，试图同时保留可复现性和与专家判断的一致性。
  - 评测规模扩大到 4.3k 案例，并首次把表单和完整图表数值纳入六维评测。
- 启示：
  - 选型或自研文档解析时，应使用按严重度加权的指标，避免被无害格式差异抬高或压低分数。
- 标签：document-parsing,benchmark,parsebench,llamaindex
- 资源：github=https://github.com/run-llama/ParseBench；hf=https://huggingface.co/datasets/llamaindex/ParseBench-2；paper=https://www.llamaindex.ai/files/parsebench-v2-severity-aware-evaluation-of-document-parsing.pdf；x=https://x.com/jerryjliu0/status/2120921239619612921

## RAGFlow 1.0 发布，定位从端到端 RAG 引擎转向 Agent Native Database
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://ragflow.io/blog/announcing-ragflow-1.0-beyond-rag-toward-an-agent-native-database
- 要点：2026-11-09，RAGFlow 发布 1.0，正式把产品定位为 Agent Native Database，即 Agent Harness 可直接调用的上下文供给层；底层改写为 Go。它不再只做“检索片段再塞进提示词”，而是在索引时做 Knowledge Compilation，按需提供编译后的证据单元、导航结构、关系骨架、时间线、Wiki、本体断言和 Memory facts。官方把分工概括为：Harness 负责编排，RAGFlow 负责供给。
- 摘要：
  - 1.0 的核心变化是产品定位：从端到端 RAG 引擎变成给 Agent Harness 用的上下文供给层。
  - Knowledge Compilation 把理解工作前移到索引阶段，目标是一次编译、多次调用。
- 启示：
  - 建设企业知识库时，可把“编排检索的 Harness”和“持续供给高质量上下文的层”分开设计，而不是只堆更复杂的召回算法。
- 标签：rag,agentic-search,knowledge-compilation,ragflow

## Neo4j 开源 graph-explorer-kit：把 Document Intelligence 图谱交给 Agent 工具和 HTTP API
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://neo4j.com/blog/developer/agentic-graphrag-and-an-explorer-for-your-own-stack/
- 要点：2026-11-09，Neo4j 开发者倡导者 Zaid Zaim 介绍开源 graph-explorer-kit（基于 neo4j-graphrag）。Aura 的 Document Intelligence 先把文件切块、抽实体并保留出处，随后可用该工具包：在自己的代码里调用 retriever、把检索工具交给自己的 Agent，或调用 HTTP API（POST /api/ask 与 /api/ask/stream）。Agent 可选用混合检索、只读 Cypher、实体查找和 graph_overview；写入查询会被拒绝。仓库：https://github.com/ZaidZaim/graph-explorer-kit。
- 摘要：
  - 该套件把“文件生成带出处的图谱”和“让 Agent 按问题选择检索工具”连成一条可嵌入应用的路径。
  - 图谱查询默认只读，实体可回溯到原文段落和源文件。
- 启示：
  - 做 GraphRAG 时，应为 Agent 同时提供文本混合检索和只读图查询，并保留实体到原文的出处链接。
- 标签：graphrag,neo4j,agentic-search,provenance
- 资源：github=https://github.com/ZaidZaim/graph-explorer-kit

## Flexible GraphRAG 0.10.0 增加 Graph 标签页，可视化文档抽取的实体与关系
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://integratedsemantics.org/2026/11/
- 要点：2026-11-10 发布的 Flexible GraphRAG v0.10.0 在 React、Vue、Angular 应用以及面向 Alfresco 和 Nuxeo 的 KG Spaces 中新增 Graph 标签页，用于展示一次摄入、混合检索、问答来源或所选文档/文件夹对应的实体与关系，并支持按类型开关、展开邻居和导出；只显示当前用户有权阅读的文档。该标签页可对接其支持的全部 15 种属性图。同版本还改进了弱匹配过滤、Ollama 上下文窗口，以及删除或重新同步文档时保留其他文档仍在使用的实体和关系。项目采用 Apache 2.0 许可。
- 摘要：
  - 0.10.0 的主要可见变化是把自动抽取的知识图谱直接呈现在应用和内容管理系统里。
  - 同版本也修了跨文档共享关系在删除或重同步时被误伤的问题。
- 启示：
  - 知识图谱只有在用户能按文档权限查看、过滤和回溯时，才比较容易进入日常检索和问答流程。
- 标签：graphrag,opensource,visualization
- 资源：github=https://github.com/stevereiner/flexible-graphrag；docs=https://stevereiner.github.io/flexible-graphrag/
