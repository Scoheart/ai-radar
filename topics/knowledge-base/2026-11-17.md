## Amazon Bedrock 托管知识库新增表格搜索：在沙箱中对整表跑代码再与文档一起作答
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://aws.amazon.com/blogs/machine-learning/get-answers-from-tables-with-tabular-search-in-amazon-bedrock-managed-knowledge-base/
- 要点：AWS 于 11-16 宣布 Amazon Bedrock Managed Knowledge Base 支持 tabular search。当问题需要 CSV、XLSX 或 XLS 中的数据时，检索先定位到表格文件，再在无网络沙箱中对原文件执行模型生成的代码，把计算结果与相关文档一起作答；该流程走已有的 AgenticRetrieveStream，无需单独开启或预先定义 schema。因为至少多一轮 Agent 周转，含表格的回答会比纯文本更慢。官方明确它不替代受治理的指标、定期看板和数仓级关联。未做独立复现。
- 摘要：
  - 对 CSV / XLSX / XLS，检索只需命中表格文件，随后在无网络沙箱中对原文件执行模型生成的代码，再与相关文档一起回答分析性问题；走已有 AgenticRetrieveStream，无需单独开启或预定义 schema。
  - 该路径至少多一轮 Agent 周转，延迟高于纯文本检索；官方明确不替代受治理的指标、定期看板和数仓级关联。
- 启示：
  - 表格问答应把「定位到哪张表」和「对整表计算」拆开，避免只靠切片检索去拼总数或做阈值判断。
  - 审计应看 trace 里读了哪些文件，而不是指望系统返回生成代码（官方因可能回显单元格而不返回代码）。
- 标签：bedrock,rag,tabular,agentic-retrieval
- 资源：docs=https://docs.aws.amazon.com/bedrock/latest/userguide/knowledge-base.html

## Amazon S3 Vectors 支持向量与全文混合检索，用于 RAG 与 Agent 记忆
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://aws.amazon.com/about-aws/whats-new/2026/11/s3-vectors-hybrid-search/
- 要点：AWS 于 11-16 宣布 Amazon S3 Vectors 支持混合检索：同一 QueryVectors 请求同时做向量相似与全文检索，再用 Reciprocal Rank Fusion 合成一份 Top-K。可检索文本作为元数据字段随 PutVectors 写入，系统按 BM25 建索引；也支持分开查询后自排，并可为已有数据就地启用全文检索。官方称偶发查询仍为亚秒级，频繁查询延迟约 100 毫秒或更低，适用 RAG、Agent 记忆和搜索。已在所有提供 S3 Vectors 的商业区域及 AWS 中国区域上线。未做独立复现。
- 摘要：
  - 同一 QueryVectors 请求同时做向量相似与 BM25 全文检索，再用 RRF 合成一份 Top-K；可把可检索文本作为元数据字段写入，也支持分开查询后自排。
  - 官方称偶发查询仍为亚秒级，频繁查询延迟约 100 毫秒或更低；已在所有提供 S3 Vectors 的商业区域及 AWS 中国区域上线。
- 启示：
  - 新建 RAG 或 Agent 记忆检索时，可先验证同一存储内的混合检索，而不是只上向量、事后再补关键字通道。
  - 已有 S3 Vectors 数据可就地为文本字段建全文索引，迁移前应按官方 API 先做一次对照。
- 标签：s3-vectors,hybrid-search,rag,agent-memory
- 资源：docs=https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors.html
