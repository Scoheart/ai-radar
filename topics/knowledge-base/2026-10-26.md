## OCRia-1 发布 37 页技术报告：4B 文档解析 VLM 的数据与训练全流程
- 来源：网页/文档　记录者：知识库
- 链接：https://www.llamaindex.ai/ocria/ocria-1-technical-report.pdf
- 要点：LlamaIndex 公开 OCRia-1 技术报告，在 ParseBench、olmOCR-bench、PulseBench-Tab、fr-bench-pdf2md 上与 Infinity-Parser、LightOnOCR 3、Chandra 2、dots.mocr 等开源模型对比，并披露文档数据筛选与训练管线；解码速度比同类开源模型快 2–4 倍，附 24 页实验附录，适合自研解析模型或选型参考。
- 摘要：
  - 报告把 OCRia-1 放在 ParseBench、olmOCR-bench、PulseBench-Tab 和 fr-bench-pdf2md 上，对照 Infinity-Parser、LightOnOCR 3、Chandra 2、dots.mocr 等开源解析模型。选型时这四套基准一起看，不要只留一个总分。
  - 报告公开了文档数据筛选和训练管线，并附了 24 页实验附录。自研解析模型时，管线和附录里的设置可以对照，不只有榜单分数。
  - 解码速度比同类开源模型快 2 到 4 倍。速度和表格、版面类基准是分开的指标，快不代表每一类版式都领先。
- 启示：
  - 自研文档解析时，把数据筛选和训练管线对照这份报告，不要只比一个榜的分数。24 页附录里的实验设置先列成清单，我们缺的环节再补实验，而不是整段搬超参。
  - 选型同时看解码速度和表格、版面类基准。速度优势是相对同类开源模型的 2 到 4 倍；表格和版面至少看 PulseBench-Tab，再和 ParseBench、olmOCR-bench、fr-bench-pdf2md 对照。
  - 对照模型写全名字：Infinity-Parser、LightOnOCR 3、Chandra 2、dots.mocr。内部对比表若少了其中一列，不要把「领先开源」写成已经覆盖这些模型。
- 标签：文档解析,OCR,VLM

## SearchWeaver：让 Agent 自动优化检索接口（语料产物+工具+指令）
- 来源：网页/文档　记录者：知识库
- 链接：https://arxiv.org/abs/2610.29250
- 要点：KAIST/高丽大学提出用编码 Agent 读搜索轨迹和奖励，联合改写语料预处理产物（如标题索引）、可执行检索工具与使用说明。GPT-5.4-nano 上 BrowseComp-Plus 准确率 71.6%→78.4%，BRIGHT 四子集 nDCG@10 45.7→55.0，工具耗时降 22–42%，接口可迁移到 Gemini 3.5 Flash-Lite。说明企业知识库的检索接口应按语料定制而非一套通用。
- 摘要：
  - 编码 Agent 读搜索轨迹和奖励，同时改写三样东西：语料预处理产物（例如标题索引）、可执行的检索工具，以及给 Agent 的使用说明。改的是检索接口，不是只调一个相似度阈值。
  - 在 GPT-5.4-nano 上，BrowseComp-Plus 准确率从 71.6% 提到 78.4%。BRIGHT 四个子集的 nDCG@10 从 45.7 提到 55.0。两套基准都要报，不能只留涨得更多的那一个。
  - 工具耗时下降 22% 到 42%。改好的接口可以迁到 Gemini 3.5 Flash-Lite，说明它不是只对训练时那个模型有效。企业知识库应按自己的语料定制接口，而不是套一套通用检索。
- 启示：
  - 企业知识库不要先上一套通用检索接口。按这里的做法，用编码 Agent 读搜索轨迹和奖励，同时改语料产物、检索工具和使用说明。先拿一条真实查询轨迹试改这三样，而不是只调阈值。
  - 改完用原文的两套数验收：GPT-5.4-nano 上 BrowseComp-Plus 从 71.6% 到 78.4%，BRIGHT 四子集 nDCG@10 从 45.7 到 55.0，工具耗时降 22% 到 42%。准确率和耗时一起看，只涨一个不算过。
  - 接口要在另一个模型上再跑一遍。原文迁到了 Gemini 3.5 Flash-Lite。我们至少再拿一个非训练模型跑同一批查询，确认说明和工具不是绑死在一个模型上。
- 标签：agentic-search,检索接口,BRIGHT,BrowseComp-Plus

## Cohere Rerank 5：Pro/Fast 两档 + Context Focus 段落级重排
- 来源：网页/文档　记录者：知识库
- 链接：https://cohere.com/blog/rerank-5
- 要点：10-21 发布，Rerank 5 Pro 在 nanoMTEB、ViDoRe V3、BRIGHT 上领先，Fast 吞吐约为 Pro 的 3 倍；新增 Context Focus，一次调用返回文档内最相关段落及分数，官方称最多省 41% token；分数跨查询校准，可用单一阈值决定送入 LLM 的内容。支持 API、VPC 与本地部署，Pro $0.05/百万 token。
- 启示：
  - 重排分成 Pro 和 Fast 两档，不要默认全程用 Pro。Fast 吞吐约为 Pro 的 3 倍；Pro 在 nanoMTEB、ViDoRe V3 和 BRIGHT 上领先，价格是每百万 token 0.05 美元。延迟敏感的路径先试 Fast，质量不够再切 Pro。
  - 送进 LLM 之前用 Context Focus，一次调用拿回文档内最相关的段落和分数。官方称最多省 41% token。先在我们最长的几类文档上量实际节省，不要把「最多 41%」写成每一份文档的承诺。
  - 分数跨查询做过校准，可以用同一个阈值决定哪些段落送进模型。上线前用一批查询标定这个阈值，并确认 API、VPC 和本地部署里分数的口径一致。这是 10 月 21 日发布的行为，换版本时重新标定。
- 标签：rerank,RAG,企业检索
- 资源：docs=https://docs.cohere.com/docs/rerank-overview；x=https://x.com/cohere/status/2112923503100125326
