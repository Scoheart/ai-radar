## TASK Memory：正确记忆进了提示，模型仍可能忽略或用错对象
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.34762
- 要点：北航团队把“记忆已正确取回并放入提示，但回答仍与之矛盾或用到了错误对象”称为使用时记忆幻觉。在五个开源模型上，忽略记忆最高达 46%，把记忆用到邻近实体最高达 24%，若再叠加权重编辑可达 49%；在同时存有新旧版本时，53% 的回答仍给出已被替代的值。TASK 给每条记忆同时配备文本、可移除的知识编辑和一对不存内容的激活引导向量，由查询是否命中同一地址来决定采用记忆还是保留模型自己的答案。在预先登记、只测一次的协议下，作者报告十个模型–数据集格子中忽略记忆均降至不超过 1.5%，邻近误用从 39.2% 降到 7.5%；在 300 条记忆库上比 BM25 RAG 高 16.4 个百分点，3,000 条时优势仍在。23 项跨模型比较中有 21 项显著。实验主要在事实编辑和多跳问答上，不是通用智能体任务。分数来自论文，未见公开实现，未独立复现。据 X 上的报道，有账号同步讨论了这些数字。
- 摘要：
  - 使用时幻觉不是存错了：正确记忆已在提示里，忽略记忆仍可高达 46%，用错对象可达 24%。
  - 在预先登记、只测一次的设置下，忽略记忆降到不超过 1.5%，CounterFact 上邻近误用从 39.2% 降到 7.5%。
  - 实验主要在事实编辑和多跳问答上，还不能直接当成通用智能体记忆任务的结论。
- 启示：
  - 评测记忆系统时，除了检索是否命中，还应单独统计：模型是否采用了已注入的记忆，以及是否把它用到了错误实体或过期版本。
- 标签：memory,task-memory,hallucination,knowledge-editing,activation-steering
- 资源：x=https://x.com/hlr_newsletter/status/2125914982596419735

## MGMem：不做生成式索引，直接用确定性提及图取回原始对话
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.33174
- 要点：港科广提出 MGMem：构建索引时不调用生成式 LLM，而是用判别式解析得到跨 session 的提及关联图，再用主语条件的三阶段解析定位问题对象，并把原始对话片段交给阅读器。作者在本地三次匹配协议重跑中报告，LoCoMo 准确率为 75.89±0.10%，比 EMem 高 2.60 个百分点、比 LightMem 高 13.47 个百分点，且生成式索引调用为零；片段检索 hit@1/5/10 为 0.591/0.837/0.893。对照系统为十段 LoCoMo 对话构建记忆，平均需要 309 到 6081 次生成式索引调用。在完整 LongMemEval-S（500 题）上，MGMem 为 72.60%，低于 BM25 的 74.60% 和 Hybrid 的 73.80%。代码已开源。分数来自论文，未独立复现。
- 摘要：
  - 在匹配协议的 LoCoMo 上，三次运行为 75.89±0.10%，高于 EMem 和 LightMem，且构建索引不调用生成式模型。
  - 在完整 LongMemEval-S 上为 72.60%，低于 BM25 的 74.60%，优势不能直接外推到所有记忆基准。
  - 生成式索引在十段对话上就要数百到数千次调用，且重复运行会写出不同摘要或图谱。
- 启示：
  - 若记忆需要可复现和可追溯到原话，应把“是否用 LLM 改写历史”当成单独的设计选择，并同时报告构建成本和原话命中率。
- 标签：memory,mgmem,locomo,longmemeval,provenance
- 资源：github=https://github.com/junhong-h/MGMem

## HoMe：用失败归因自动改记忆系统的 harness，分数略升、查询 token 明显下降
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.34624
- 要点：上海交大、阿里巴巴和北大提出 HoMe，在开源记忆系统 ReMe 上自动优化由代码、提示和配置组成的 harness。框架用 session 级记忆版本和执行轨迹定位共性失败，再结合候选门控、冒烟测试、自适应抽样和记忆复用控制评估成本。在每个基准做完一次完整初评后，再做六次正式候选评估。官方博客与论文同步给出：LongMemEval-S 从 88.8% 升到 91.6%，每查询 token 从 43.9K 降到 17.9K（减少 59.2%）；BEAM-1M 从 65.0% 升到 70.4%，token 从 101.8K 降到 60.4K（减少 40.7%）。代码在 ReMe 仓库中。分数来自作者，未独立复现。
- 摘要：
  - 在 ReMe 上只做六次正式候选评估后，LongMemEval-S 从 88.8% 升到 91.6%，查询阶段 token 减少 59.2%。
  - BEAM-1M 从 65.0% 升到 70.4%，查询阶段 token 减少 40.7%。
- 启示：
  - 优化记忆系统时，可以把代码、提示和配置当成同一个 harness 来迭代，并用失败轨迹定位是构建、检索还是回答环节出了问题，同时跟踪查询 token，而不是只看准确率。
- 标签：memory,home,reme,longmemeval,beam,harness
- 资源：github=https://github.com/agentscope-ai/ReMe；blog=https://reme.agentscope.io/en/blog_20261124
