## Amazon OpenSearch Memory 正式商用，为 Agent 提供无服务器长期记忆
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://aws.amazon.com/about-aws/whats-new/2026/11/amazon-opensearch-memory-generally-available/
- 要点：AWS 于 2026-11-18 宣布 Amazon OpenSearch Memory 正式商用。它是 OpenSearch Service 中的无服务器能力：把 Agent 交互按原文存成可搜索事件（官方称数秒内可检索），再异步抽取结构化记忆，并完成提取、嵌入、索引、合并（新增、更新或跳过）以及关键词、语义和混合检索。访问控制使用 IAM，可按记忆库、行动者和会话授权，也可为事件和记忆设置过期时间。目前在弗吉尼亚北部、俄亥俄、俄勒冈、法兰克福和东京区域上线。
- 摘要：
  - 记忆服务代管提取、合并和检索，不必自建一套抽取和索引流水线。
  - 原文事件与派生记忆分开保存，并支持按行动者和会话做访问控制与过期。
- 启示：
  - 给 Agent 加长期记忆时，应同时设计原文事件可检索、结构化记忆可合并，以及按行动者/会话隔离和过期策略。
- 标签：OpenSearch,AWS,agent-memory,GA
- 资源：blog=https://aws.amazon.com/blogs/big-data/introducing-amazon-opensearch-memory-persistent-memory-for-ai-agents/；docs=https://docs.aws.amazon.com/opensearch-service/latest/developerguide/memory.html

## ARISE：企业 Agent 从失败中自演化记忆，不改模型权重和工具
- 来源：网页/文档　记录者：AI前沿者
- 链接：https://arxiv.org/abs/2611.23588
- 要点：arXiv 2611.23588 提出 ARISE：Agent 记忆从自身失败中迭代演化，不更新模型权重、工具或工作流逻辑。它用部署模型或教师模型归因失败并给出纠正，先存为可检索的微观记忆，再合并成宏观规则，只有在留出集准确率上升时才接受规则更新。在 SOP-Bench 和 τ²-bench 的 14 个企业工作流域、5 个模型上，用 Claude Opus 4.6 做归因和合并的 ARISE-Teacher 相对基线分别提高 10.9 和 5.8 个百分点，并比 GEPA 高 4.5 和 1.4 个百分点；由部署模型自己归因的 ARISE-Self 在 SOP-Bench 上也提高 10.0 个百分点。ARISE-Teacher 的模型调用少 4.0%、输出 token 少 5.2%，单任务成本大致持平（-1.0%）。
- 摘要：
  - 不改模型、工具和工作流，只靠失败归因和规则验收，就能在企业工作流基准上取得约 6–11 个百分点的准确率提升。
  - 规则更新以留出集准确率为门槛，避免把未经验证的纠正直接写进长期记忆。
- 启示：
  - 企业 Agent 记忆更新应设验收门槛：先把失败纠正写成可检索条目，再在留出集上确认有效后才提升为稳定规则。
- 标签：ARISE,agent-memory,SOP-Bench,enterprise
