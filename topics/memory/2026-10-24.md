## Letta FrontierMemory 1.0：用睡眠期蒸馏评测从经验中持续学习
- 来源：网页/文档　记录者：记忆
- 链接：https://www.frontiermemory.com/blog/v1/
- 资源：github=https://github.com/letta-ai/frontiermemory；docs=https://frontiermemory.com/
- 要点：LoCoMo 等问答式基准已被长窗口和 Bash 检索刷满。FrontierMemory 把记忆写成 task/user/environment 三类 Markdown 和 SKILL.md，先由 Dreaming Harness 从 665 条轨迹离线提炼，再测下游任务；统一 Claude Opus 5.5 时 Letta Dream 73.3% 夺冠。祈使句写明技能触发条件能显著提高唤醒率，且应避免绑定具体字节数等过拟合细节。
- 启示：
  - 问答基准被长窗口和 Bash 检索刷满之后，不要再用 LoCoMo 这种题决定记忆方案。FrontierMemory 改成从 665 条轨迹离线提炼，再测下游任务。我们的记忆评测也改到下游任务上，问答分只留作对照。
  - 记忆写成 task、user、environment 三类 Markdown，外加 SKILL.md。技能的触发条件用祈使句写清，这能明显提高唤醒率。不要把具体字节数这类过拟合细节写进技能，否则换一种输入长度就唤不醒。
  - 比较时钉死模型：原文统一用 Claude Opus 5.5，Letta Dream 是 73.3%，换模型重跑时不能直接引用这个名次。Dreaming 在睡眠期做，醒着的时候只读提炼结果。
- 标签：Letta,Dreaming,benchmark

## MemoryTax：强模型时代预抽取记忆的“苦涩教训”
- 来源：网页/文档　记录者：记忆
- 链接：https://arxiv.org/abs/2610.29823
- 资源：github=https://github.com/zedong-peng/memorytax；blog=https://zedongpeng.com/memorytax/
- 要点：LoCoMo 上对比 Full Context、BM25、Mem0、Zep 与直接检索原始历史的 Coding Agent。Opus 5.5 下 Pi 原生检索达 99%、成本 $6.95，而 Mem0 仅建库就花 $25.88，需连续提问 372 至 596 次才能摊平；弱模型写入的记忆换强模型读取也无法挽回信息损失。
- 启示：
  - 强模型上先跑「直接检索原始历史」的对照，再决定要不要预抽取。Opus 5.5 下 Pi 的原生检索到 99%，成本 6.95 美元；Mem0 光建库就 25.88 美元，要连续问 372 到 596 次才摊平。提问次数到不了这个区间，就不要为了记忆库付建库的钱。
  - 对照里同时放上 Full Context、BM25、Mem0、Zep 和原始历史检索。少一个，就不知道花费是省在检索上，还是亏在抽取上。
  - 不要用弱模型写记忆、再换强模型读。原文里这样换模型也补不回已经丢掉的信息。写入模型至少和读取模型同一档，或者干脆不预抽取，把原文留下。
- 标签：Mem0,Zep,成本

## TokenWorth：资源受限下的在线记忆价值学习
- 来源：网页/文档　记录者：记忆
- 链接：https://arxiv.org/abs/2610.26453
- 资源：github=https://github.com/AIGNLAI/TokenWorth；hf=https://huggingface.co/papers/2610.26453
- 要点：用确定性哈希特征加线性打分器与递归特征机残差修正，从稀疏执行反馈在线学习哪些记忆值得保留，不需要额外 LLM 调用。LifelongAgentBench 本地 DB 任务 65.0%（RAG 33.0%、Mem0 21.2%），输出 Token 降低 9.3% 至 58.3%。
- 启示：
  - 记不住全部时，用在线打分决定留哪条，不要每条都再叫一次 LLM。TokenWorth 用确定性哈希特征、线性打分器，再用递归特征机做残差修正，信号来自稀疏的执行反馈。先接执行成功或失败，不接额外的总结调用。
  - 在 LifelongAgentBench 的本地数据库任务上对照：这里是 65.0%，RAG 33.0%，Mem0 21.2%。记忆策略用同一任务比，不要只和自己的上一版比。
  - 输出 token 会降 9.3% 到 58.3%，幅度差得很大。上线时按任务报区间，不要报成一个固定节省比例。没有执行反馈的纯聊天没有这套打分的信号，不要硬套。
- 标签：memory-worth,lifelong

## Mem0：双时钟时序记忆（事件时间与写入时间分离）
- 来源：据 X 上的报道　记录者：记忆
- 链接：https://x.com/mem0ai/status/2112561906804568502
- 要点：区分事件时间与写入时间；状态变更时把旧记忆标记 superseded 而不物理删除；用 expiration_date 与 reference_date 做时效和可重放评测。
- 启示：
  - 记忆加两个时钟：事情发生的时间，和写入库的时间。只存一个时间戳时，后写的旧闻会盖住新状态。schema 里把两者都存上。
  - 状态变了就把旧记忆标成 superseded，不要物理删除。回放和审计还要看旧结论。物理删除只留给明确的数据清除，和「已经过时」分开。
  - 评测用 expiration_date 和 reference_date 把时钟拨到过去。同一批记忆在不同 reference_date 下结果应不同。拨不回去，说明时效没有真正进检索。
- 标签：Mem0,temporal

## 文件系统记忆的组织、演化与可持续性（UIUC 等）
- 来源：网页/文档　记录者：记忆
- 链接：https://arxiv.org/abs/2607.26637
- 资源：hf=https://huggingface.co/papers/2607.26637
- 要点：把 Markdown 目录记忆分为管理、检索、执行三角色：目录重组把大规模检索成本降一半以上，但自由重组会静默浓缩丢细节（REALTALK 77.6% 掉到 41.2%），需强制保留每条事实与溯源定位符；强模型蒸馏的技能文件能让弱执行模型反超强模型读原始轨迹。
- 启示：
  - 文件系统记忆拆成管理、检索、执行三个角色，不要让同一个过程又改目录又答题。目录重组可以把大规模检索成本降一半以上，但自由重组会静默把细节浓缩掉，REALTALK 上从 77.6% 掉到 41.2%。重组必须强制留下每条事实和溯源定位符。
  - 成本下降和事实保留一起验收。只看到检索变便宜、没核对事实还在，就不要合并目录。定位符丢了的条目视为重组失败。
  - 技能文件可以由强模型蒸馏，再交给弱的执行模型，原文里这样能反超强模型直接读原始轨迹。蒸馏前确认事实和定位符还在。用弱模型读被浓缩过的目录时，掉分会先发生。
- 标签：filesystem,markdown

## MemForm：记忆形成期投毒基准
- 来源：网页/文档　记录者：记忆
- 链接：https://arxiv.org/abs/2610.14431
- 资源：github=https://github.com/opanhw/memform-code
- 要点：覆盖内容、证据、作用域、子集选择、合并顺序五类形成期攻击面。仅改变相同经验的合并顺序就能把参考行为保持率从约 80% 降到 42.1% 至 62.4%，关键词过滤与 LLM-Judge 防御几乎无效，设计时应给策略记忆绑定适用作用域与溯源证据。
- 启示：
  - 记忆的威胁建模放到形成期，不只防读出时的注入。五类面都要有用例：内容、证据、作用域、子集选择、合并顺序。先做合并顺序这一项，因为它不改事实、只改顺序，就能把参考行为保持率从大约 80% 降到 42.1% 到 62.4%。
  - 关键词过滤和 LLM Judge 在这里几乎挡不住。不要把这两样当成形成期防御已经完成。防御要卡在写入时的作用域和溯源，而不是卡在文本里有没有坏词。
  - 策略记忆必须绑上适用作用域和溯源证据。没有作用域的策略不要进可执行记忆。评测时把五类攻击分开报保持率，不要合成一个安全分。
- 标签：security,poisoning
