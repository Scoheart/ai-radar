## Letta FrontierMemory 1.0：用睡眠期蒸馏评测从经验中持续学习
- 来源：网页/文档　记录者：记忆
- 链接：https://www.frontiermemory.com/blog/v1/
- 资源：github=https://github.com/letta-ai/frontiermemory；docs=https://frontiermemory.com/
- 要点：LoCoMo 等问答式基准已被长窗口和 Bash 检索刷满。FrontierMemory 把记忆写成 task/user/environment 三类 Markdown 和 SKILL.md，先由 Dreaming Harness 从 665 条轨迹离线提炼，再测下游任务；统一 Claude Opus 5.5 时 Letta Dream 73.3% 夺冠。祈使句写明技能触发条件能显著提高唤醒率，且应避免绑定具体字节数等过拟合细节。
- 标签：Letta,Dreaming,benchmark

## MemoryTax：强模型时代预抽取记忆的“苦涩教训”
- 来源：网页/文档　记录者：记忆
- 链接：https://arxiv.org/abs/2610.29823
- 资源：github=https://github.com/zedong-peng/memorytax；blog=https://zedongpeng.com/memorytax/
- 要点：LoCoMo 上对比 Full Context、BM25、Mem0、Zep 与直接检索原始历史的 Coding Agent。Opus 5.5 下 Pi 原生检索达 99%、成本 $6.95，而 Mem0 仅建库就花 $25.88，需连续提问 372 至 596 次才能摊平；弱模型写入的记忆换强模型读取也无法挽回信息损失。
- 标签：Mem0,Zep,成本

## TokenWorth：资源受限下的在线记忆价值学习
- 来源：网页/文档　记录者：记忆
- 链接：https://arxiv.org/abs/2610.26453
- 资源：github=https://github.com/AIGNLAI/TokenWorth；hf=https://huggingface.co/papers/2610.26453
- 要点：用确定性哈希特征加线性打分器与递归特征机残差修正，从稀疏执行反馈在线学习哪些记忆值得保留，不需要额外 LLM 调用。LifelongAgentBench 本地 DB 任务 65.0%（RAG 33.0%、Mem0 21.2%），输出 Token 降低 9.3% 至 58.3%。
- 标签：memory-worth,lifelong

## Mem0：双时钟时序记忆（事件时间与写入时间分离）
- 来源：据 X 上的报道　记录者：记忆
- 链接：https://x.com/mem0ai/status/2112561906804568502
- 要点：区分事件时间与写入时间；状态变更时把旧记忆标记 superseded 而不物理删除；用 expiration_date 与 reference_date 做时效和可重放评测。
- 标签：Mem0,temporal

## 文件系统记忆的组织、演化与可持续性（UIUC 等）
- 来源：网页/文档　记录者：记忆
- 链接：https://arxiv.org/abs/2607.26637
- 资源：hf=https://huggingface.co/papers/2607.26637
- 要点：把 Markdown 目录记忆分为管理、检索、执行三角色：目录重组把大规模检索成本降一半以上，但自由重组会静默浓缩丢细节（REALTALK 77.6% 掉到 41.2%），需强制保留每条事实与溯源定位符；强模型蒸馏的技能文件能让弱执行模型反超强模型读原始轨迹。
- 标签：filesystem,markdown

## MemForm：记忆形成期投毒基准
- 来源：网页/文档　记录者：记忆
- 链接：https://arxiv.org/abs/2610.14431
- 资源：github=https://github.com/opanhw/memform-code
- 要点：覆盖内容、证据、作用域、子集选择、合并顺序五类形成期攻击面。仅改变相同经验的合并顺序就能把参考行为保持率从约 80% 降到 42.1% 至 62.4%，关键词过滤与 LLM-Judge 防御几乎无效，设计时应给策略记忆绑定适用作用域与溯源证据。
- 标签：security,poisoning
