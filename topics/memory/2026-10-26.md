## Raw-RAG：朴素 RAG 在 7 个设置中 6 个胜过 12 种 Agent 记忆系统
- 来源：网页/文档　记录者：记忆
- 链接：https://arxiv.org/abs/2610.30755
- 资源：github=https://github.com/Litmeb/RAW-RAG；hf=https://huggingface.co/papers/2610.30755
- 要点：原始对话按 256 token、32 重叠切窗，稠密检索 Top-128 后交叉编码器重排到 Top-15，不做任何 LLM 抽取、摘要或建图。在 LoCoMo、LongMemEval、MEME、MemoryAgentBench 上 7 个设置中 6 个第一，领先最强 Agent 记忆 0.13 至 5.53 分；加原子事实抽取让 MemoryAgentBench 总分掉 19.62 分，三种记忆管理增强需 2160 万至 1.093 亿 LLM Token，原始证据的覆盖率优势胜过变换后记忆的利用率。
- 摘要：
  - Raw-RAG 只做切窗、稠密检索和交叉编码器重排，不做 LLM 抽取、摘要或建图。切窗是 256 token、重叠 32；先取稠密检索的 Top-128，再重排到 Top-15。
  - 在 LoCoMo、LongMemEval、MEME 和 MemoryAgentBench 上，7 个设置里有 6 个排在所比较的 Agent 记忆系统前面。领先最强的那套 Agent 记忆 0.13 到 5.53 分。
  - 加上原子事实抽取后，MemoryAgentBench 总分下降 19.62 分。三种记忆管理增强要消耗 2,160 万到 1.093 亿 LLM token。原文把这解释成原始证据的覆盖率，胜过变换之后记忆的利用率。
- 启示：
  - 上记忆系统之前，先用切窗、检索和重排的朴素 RAG 做对照。对照设置写明 256 token、重叠 32、Top-128 再重排到 Top-15。换一套切分再声称打平了朴素 RAG，就不能和这里的 6/7 比。
  - 每加一层抽取或建图，都要同时量准确率和 token。原子事实抽取让 MemoryAgentBench 掉了 19.62 分；三种记忆管理增强要 2,160 万到 1.093 亿 token。准确率没涨、token 先涨的层，不要留在默认路径里。
  - 基准至少覆盖 LoCoMo、LongMemEval、MEME 和 MemoryAgentBench 里我们在用的那几个，并分开报 7 个设置。领先幅度是 0.13 到 5.53 分，小的那头可能翻篇，不要只用最大分差做决定。
- 标签：RAG,baseline,benchmark

## Tether：给记忆判定绑定依赖版本，上游失效时读时撤回
- 来源：网页/文档　记录者：记忆
- 链接：https://arxiv.org/abs/2610.25123
- 资源：github=https://github.com/xiaoqi-7/tether-fallout
- 要点：原子事实记忆里每条记录写入时都为真，但上游签名密钥吊销等失效不会与下游判定同处一个检索窗口，导致 Agent 发布 62% 的上游已失效对象。Tether 写入时记录判定所依赖的确切版本，读取时撤回依赖已失效的判定，不安全发布降到 0.3%，验证调用少 37%；对比 Mem0 42%、A-Mem 与 Graphiti 9%。依赖关系若在其他会话才出现，不安全率回升到 9.4% 至 22.1%。
- 摘要：
  - 原子事实在写入时为真，但上游失效（例如签名密钥吊销）和下游判定往往不在同一个检索窗口。Agent 因此发布了 62% 已经失效的对象。只存「当时为真」的事实，挡不住后来的失效。
  - Tether 在写入时记下判定依赖的确切版本，读取时撤回依赖已失效的判定。不安全发布降到 0.3%，验证调用少 37%。版本绑在判定上，而不是只在对象上打一个过期时间。
  - 作为对照，Mem0 的不安全发布是 42%，A-Mem 和 Graphiti 是 9%。Tether 的 0.3% 是相对这些系统的结果，不是零风险。
  - 依赖如果出现在别的会话里，不安全率会回到 9.4% 至 22.1%。跨会话才出现的依赖，不在写入时那条记录的版本里。
- 启示：
  - 记忆里的判定要写上它依赖的上游版本，读取时检查这些版本是否已失效，失效就撤回，不要等检索窗口碰巧同时含有失效事件。先从签名密钥、权限这类会吊销的上游做起。这里不撤回时，62% 的已失效对象会被发出去。
  - 对照不要只和「无记忆」比。原文的对照是 Mem0 42%、A-Mem 和 Graphiti 9%，Tether 把不安全发布降到 0.3%，验证调用少 37%。我们加版本绑定后，用同一套不安全发布比例和验证调用次数验收。
  - 依赖若出现在别的会话，不安全率会回到 9.4% 到 22.1%。跨会话的依赖要单独进写入时的版本记录，不能假设当前窗口已经看见。这条回升说明 0.3% 只在依赖当时就写进记录时成立。
- 标签：invalidation,provenance,Mem0

## supermemory 发布 learner-1：面向任意模型的上下文内持续学习
- 来源：据 X 上的报道　记录者：记忆
- 链接：https://x.com/supermemory/status/2114491489648853364
- 要点：learner-1 对每个用户、任务和租户的上下文做抽取与离线“做梦”，在向量-图数据库上执行更新、合并、推断与遗忘，再通过 hooks 实时把记忆 Token 注入 Agent 上下文；主张学习与记忆独立于模型厂商，可跨模型、跨 Harness 携带。
- 启示：
  - 记忆层按用户、任务和租户分开抽取，不要所有会话写进一个池。learner-1 在离线阶段做更新、合并、推断和遗忘，再经 hooks 把记忆 token 注入上下文。先定遗忘规则，再开推断，避免推断出的内容和原文混在一起。
  - 存储是向量-图数据库，它主张学习与记忆不绑模型厂商，可以跨模型和跨 Harness 携带。我们用两个 Harness 读同一用户的记忆，确认 hooks 注入的 token 一致。不一致就不要把它当成可携带的记忆层。
  - 离线「做梦」和在线注入分开部署。做梦失败不应挡住当前对话。注入的 token 要能指回是更新、合并还是推断，推断结果默认降权。
- 标签：supermemory,continual-learning,dreaming
- 资源：docs=https://supermemory.ai/llms.txt；github=https://github.com/supermemoryai

## tigerless-labs/agent-memory：Markdown 为真源的本地长期记忆运行时走红
- 来源：网页/文档　记录者：记忆
- 链接：https://github.com/tigerless-labs/agent-memory
- 要点：以纯 Markdown 作为唯一真源，本地 SQLite 排序检索，外加独立的睡眠期 Manage 层整理记忆；Claude Code 与 Codex 共用一个存储，无需 API Key，MIT 许可，GitHub 已 4.7k Star。
- 启示：
  - 本地长期记忆以 Markdown 为唯一真源，SQLite 只做排序检索。不要让数据库里的行反过来改写 Markdown。改记忆时先改文件，再看检索排序是否跟上。
  - 整理放在独立的睡眠期 Manage 层，不放在对话当中。Manage 要保留被合并条目的原文，避免整理时把细节吞掉。Claude Code 和 Codex 共用这一份存储，换工具之前先确认两边读到的是同一目录。
  - 不需要 API Key，许可是 MIT，适合先在本机试。4.7k Star 只说明仓库受关注，不代替检索回归。接入前用一组已知事实检查排序有没有把真源里的句子找回来。
- 标签：filesystem,markdown,sleep-time
