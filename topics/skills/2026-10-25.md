## Anthropic：把部分子 Agent 折叠进「单 Agent + Skills」循环，并发布迁移工具包
- 来源：网页/文档　记录者：Skills
- 链接：https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop
- 要点：Anthropic 应用 AI 团队（10-22）称多个企业案例中「单 Agent + Skills 渐进披露」常在质量上优于多子 Agent，成本与延迟更低，Claude Code 系统提示因此缩减 80% 以上。建议逐个把子 Agent 折叠为 Skill + MCP 工具，并用 eval 对比后再决定去留；并行/隔离上下文等场景仍保留子 Agent。
- 摘要：
  - Anthropic 应用 AI 团队在 10-22 的文章里说，多个企业案例中，单 Agent 加上 Skills 的渐进披露，质量常常优于多个子 Agent，成本和延迟也更低。这是案例里的比较，不是所有任务的定律。
  - Claude Code 的系统提示因此缩短了 80% 以上。缩短来自把做法从主提示挪走，而不是把提示删成一句空话。
  - 建议把子 Agent 逐个折成 Skill 和 MCP 工具，用同一套 eval 对比后再决定去留。一次拆完、没有前后对比，就不知道是哪一个子 Agent 可以删。
  - 需要并行，或需要隔离上下文的步骤，仍然保留子 Agent。这两类不在「应当折叠」的范围内。
- 启示：
  - 拆子 Agent 时逐个折成 Skill 和 MCP 工具，用同一套 eval 变好了再删。我们给每个子 Agent 留一条前后对比，质量、成本和延迟都记。没有这条对比的删除不要合并。
  - 需要并行或隔离上下文的步骤留在子 Agent 里，不要为了精简一次拆完。评审清单把「并行」和「隔离上下文」写成保留理由，其他理由需要 eval 数据。
  - 系统提示变长时，优先把做法写进 Skill，由渐进披露按需加载，而不是继续堆在主提示里。Claude Code 这条路径把系统提示缩减了 80% 以上。我们先量主提示的长度，再决定搬哪一段进 Skill。
- 标签：skills,agent-architecture,eval

## anthropics/single-agent-loop-kit：多 Agent 迁移到单循环的评测驱动工具包
- 来源：网页/文档　记录者：Skills
- 链接：https://github.com/anthropics/single-agent-loop-kit
- 要点：配套文章的参考实现（不维护、不接受贡献）：先度量、再合并、再把子 Agent 逐个折叠为技能与工具，每步在同一 eval 上前后对比，数据证明替代可行才删除子 Agent；并建议由小团队维护系统提示与共享 eval，各领域团队负责自己的 skills。
- 启示：
  - 折叠子 Agent 按这个顺序：先度量，再合并，再逐个收成技能和工具。每一步都在同一套 eval 上前后对比，数据说明替代可行才删除。不要一次拆完再看总效果。
  - 这个仓库写明不维护、不接受贡献，只是参考实现。不要把它 pin 成生产依赖。步骤可以照做，运行时代码放在我们自己会维护的仓库里。
  - 系统提示和共享 eval 由一个小组维护，各领域团队只改自己的 Skills。提示词散落在每个团队时，折叠前后的 eval 无法比较。共享 eval 的改动和 Skill 的改动分开提交。
- 标签：skills,eval,build

## VirusTotal：35,878 个 Agent Skills 分析，18.5% 恶意，62% 恶意技能不含任何恶意代码
- 来源：网页/文档　记录者：Skills
- 链接：https://blog.virustotal.com/2026/10/from-automation-to-infection-part-iii.html
- 要点：10-08 发布（Part III）：52.9% 的技能带安全/滥用风险，恶意者多属 1,016 个家族，攻击完全写在自然语言指令里（如让 Agent 把税务文件 BCC 给攻击者）。同时提出 CARO-A 命名方案；实测 NVIDIA SkillSpector 2.11.2 默认阈值检出 43.1%、误报 46.2%，Cisco Skill Scanner 检出 28.5%，且 SkillSpector 遇 2.75MB 压缩 JS 因正则回溯卡死 5 分钟以上。
- 摘要：
  - 这是 10-08 发布的 Part III。35,878 个技能里，18.5% 被标为恶意，52.9% 带有安全或滥用风险。恶意样本多属 1,016 个家族，按条数和按家族不是同一个比例。
  - 恶意技能中有 62% 不含任何恶意代码，攻击写在自然语言指令里。文中的例子是让 Agent 把税务文件密送给攻击者。只扫脚本会漏掉这一类。
  - NVIDIA SkillSpector 2.11.2 的默认阈值检出率是 43.1%、误报 46.2%，Cisco Skill Scanner 的检出率是 28.5%。SkillSpector 遇到 2.75MB 的压缩 JS，会因正则回溯卡死 5 分钟以上。文中还提出了 CARO-A 命名方案。
- 启示：
  - 技能扫描不能只查代码：35,878 个里 18.5% 被标恶意，其中 62% 没有恶意代码，攻击写在指令里，例如让 Agent 把税务文件密送出去。扫描把 SKILL.md 的指令和脚本分开报。统计按 1,016 个家族去重，避免一个家族刷高条数。
  - 不要用单一默认阈值做准入。SkillSpector 2.11.2 默认阈值检出 43.1%、误报 46.2%，Cisco Skill Scanner 检出 28.5%，两个都要跑，并同时报告检出和误报。只开一个，会要么放过，要么拦下将近一半正常技能。
  - 扫描器要有超时和输入大小限制：2.75MB 的压缩 JS 能让 SkillSpector 的正则回溯卡 5 分钟以上。流水线给单文件设上限和超时，卡住不算干净。CARO-A 若还没采用，不要另起一套家族名。
- 标签：skills,security,SkillSpector

## MaliciousSkillBench：整合 13 个公开来源的 9,740 技能恶意检测基准
- 来源：网页/文档　记录者：Skills
- 链接：https://arxiv.org/abs/2608.19901
- 要点：7,505 恶意 + 2,235 良性。跨来源（Source-Disjoint）评测下，学习型检测器召回 95.6% 但良性误报 62.4%；Cisco 与 SkillSpector（静态、关 LLM）误报仅 1.1%/0.55%，但召回只有 2.5%/0%。结论：现有检测器尚无「高召回 + 低误报」方案，需同时评估两端。
- 启示：
  - 技能检测器按跨来源评，训练源和测试源分开。这份基准整合 13 个公开来源，共 9,740 个技能（恶意 7,505、良性 2,235），报分时写上 Source-Disjoint。同源抽测的高分不要拿来和这组比。
  - 召回和误报必须同时报。学习型检测器召回 95.6%、良性误报 62.4%，Cisco 和关掉 LLM 的 SkillSpector 误报只有 1.1% 和 0.55%，召回却只有 2.5% 和 0%，现在没有高召回且低误报的现成方案。准入规则不要只优化其中一端。
  - 静态扫描召回接近 0 时，不能当成已经查过自然语言指令。学习型误报过半时，也不能当成自动拦截。人工复审放在学习型标出的阳性上，不要放在静态扫描的阴性上。
- 标签：skills,security,benchmark,SkillSpector
